---
title: Divergences from CPython
description: The parity contract and every numbered difference from CPython 3.14.
---

pyscriptc targets CPython 3.14.x. Parsing, probes and the compatibility oracle follow 3.14. Compiled programs match CPython 3.14 on stdout for everything that lowers, except the numbered divergences below. The empty divergence space is load-bearing: anything not listed here is claimed identical, and a difference you find that is not listed is a bug.

## Parity contract

- stdout: byte-exact for every lowered call. The corpus scorer today compares whitespace-stripped stdout; tightening that to unstripped bytes is planned work.
- stderr: for a `raises` probe, only the exception name must appear. Full traceback text is not matched.
- exit code: an uncaught exception prints its name to stderr and exits 1, as CPython does.
- Anything that does not lower is a named `PSxxxx` fence, not a divergence. See the generated [supported](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/support/supported.md) table and [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md).

## Numbered divergences

1. `int` is `i64`. Overflow aborts the process instead of growing a big int. Source: [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md) Tier C.
2. `//` by zero aborts the process instead of raising `ZeroDivisionError`. Source: same as item 1.
3. Strings are a Latin-1 byte model. A string literal outside Latin-1 is a fence, and `unicodedata` covers only Latin-1 code points. A normalization that would leave Latin-1 raises `ValueError`. A `str` holds one byte per code point, so `len`, indexing and slicing count bytes rather than code points. Text output is not UTF-8: a program that prints a code point above U+007F writes that character as a single Latin-1 byte, where CPython writes the UTF-8 encoding, so the stdout bytes differ. The same applies to a file written in text mode and to a line read from stdin. Source: the `unicodedata` row of the generated [supported](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/support/supported.md) table, `src/pyscriptc/runtime/ps_rt.c` (`ps_case`, `ps_str_get`, `ps_str_slice`) and `src/pyscriptc/emit/llvm/_print.py`. The move to the CPython code-point model is the epic in issue [#472](https://github.com/sigilco/pyscriptc/issues/472), and this item is rewritten when it lands.
4. `re` is the runtime's byte-oriented backtracking subset, not CPython's `re`. `L`, `T`, `DEBUG` and unknown flag bits raise `ValueError`, `A` and `U` are no-ops, and a pattern that can loop without consuming stops with `RuntimeError` once its fuel is spent. Five or more groups are refused. Source: header of `src/pyscriptc/runtime/ps_re.c`, `re` row of the generated [supported](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/support/supported.md) table.
5. `json` has no non-ASCII text. Source: `json` row of the generated [supported](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/support/supported.md) table.
6. Set and `frozenset` iteration is insertion order, not CPython's hash order. Length and membership match. Source: [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md) Tier C.
7. After `for i in range(0)`, a new loop target reads as `0` instead of raising `UnboundLocalError`. Source: [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md) Tier C.
8. A subclass `__init__` that never assigns an inherited field leaves it at the zero value of its type instead of raising `AttributeError`. Source: [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md) Tier C.
9. `raise AppError("no")` for a user exception class stores a code and an optional `str` and does not call `__init__`. Source: same paragraph as item 8.
10. `@classmethod` and `@staticmethod` of the form `Class.method(...)` do not pass the class object. Source: same paragraph as item 8.
11. Some library failures surface as a different exception type: `importlib.resources.files` on a zip or missing package raises `ValueError` rather than `ModuleNotFoundError`, `shutil.copyfile` of the same path raises `RuntimeError` rather than `SameFileError`, other `shutil` and `os` failures are `RuntimeError`, and type errors on `unicodedata` calls surface as `ValueError`. Source: the `unicodedata` and `importlib.resources` rows of the generated [supported](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/support/supported.md) table.
12. `assert` is always evaluated; a compiled binary has no `-O`. Source: [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md) Tier C.
13. `x is None` lowers as `==` against `None`. Identical for `None` because it is a singleton; every other `is` on a scalar is refused. Source: [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md) Tier C.
14. `ABC`, `ABCMeta`, `Protocol`, `@abstractmethod` and `@overload` lower as plain classes and methods with no CPython runtime semantics. Source: [refused-features](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/spec/refused-features.md) Tier C.
15. Island calls (`subprocess.check_output`, `socket.gethostname`, `threading`, `logging`) run in an embedded CPython, so those follow the interpreter the binary links, not the pin.
16. `dotenv` lowers a closed subset of python-dotenv's parsing rules, and it differs from the library in three places. The subset: a UTF-8 BOM is stripped, blank lines and whole-line comments are skipped, an `export ` prefix is allowed, keys are bare (`KEY` alone binds `None`), an unquoted value runs to the end of the line with the ` #` comment cut and the rest right-stripped, a double-quoted value decodes `\" \\' \\ \a \b \f \n \r \t \v` and a single-quoted one only `\\` and `\'`, and a later binding overwrites an earlier one. No interpolation (`$NAME` stays literal), no multi-line values, no quoted keys, and the `stream`, `verbose`, `interpolate`, `override` and `encoding` arguments are fenced. The three differences: a malformed line raises `ValueError` where python-dotenv skips it with a warning, a missing file parses as the empty document where python-dotenv searches with `find_dotenv()`, and `load_dotenv` does not overwrite a variable that is already in the environment (its `override=False` default) while still returning `True` for a document with bindings. Source: header of `src/pyscriptc/runtime/ps_dotenv.c`, `dotenv` row of the generated [supported](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/support/supported.md) table.
17. `yaml.safe_load` covers a closed YAML subset, not all of PyYAML: timestamps and sexagesimal numbers (`1:30`) raise `ValueError` where PyYAML resolves them to `date` and `int` objects, and errors surface as `ValueError` rather than `yaml.YAMLError`. Source: header of `src/pyscriptc/runtime/ps_yaml.c`, `yaml` row of the generated [supported](https://github.com/sigilco/pyscriptc/blob/master/.agents/docs/support/supported.md) table.
18. HTTP and HTTPS go through a `curl` subprocess bridge, so the request is made by the host `curl` and depends on `curl` being on `PATH` at run time; a host without `curl` cannot make the call. The bridge needs the libpython-linked island shape, holds the whole body in memory with no streaming, and its TLS, proxy and redirect behavior is `curl`'s rather than CPython's. Source: the [HTTP today](https://pyscriptc.pages.dev/docs/guide/http/) page and `src/pyscriptc/runtime/ps_sub.c`.
19. `generator.send(v)` on a generator that has not started ignores `v` and runs the body from the top, where CPython raises `TypeError: can't send non-None value to a just-started generator`. `None` (the priming `send`) behaves identically in both. Source: `src/pyscriptc/coro.py` (`_GeneratorKind.methods`, the `send` entry).
20. `generator.throw(E)` marks the frame done and raises `E` out of the call site. CPython's "the generator catches it, execution continues" outcome is not reachable through this surface: `throw` is a separate entry point that never runs the generator's own `except` handlers. `GeneratorExit` semantics do not apply either: `close()` marks the frame done without running a pending `finally`, where CPython raises `GeneratorExit` inside the generator so its `finally` runs. Source: `src/pyscriptc/lower/_calls.py` (`_gen_throw`).
21. `yield from <subgenerator>` drains the subgenerator and discards its return value (`StopIteration.value`), where CPython's `yield from` expression evaluates to it. Statement-form `yield from` (the only lowered form) never reads the value, so no observable program differs. A `return <value>` in a generator lowers (the value rides in the frame) but no surface reads it back: the `StopIteration.value` of a drained generator is not reachable through the lowered generator protocol. Source: `src/pyscriptc/coro.py` (`_coro_yield_from`).
22. The `jwt` pack lowers the HMAC family only: `HS256`, `HS384` and `HS512` through `jwt.encode` and `jwt.decode` over a `dict[str, str]` payload. RS/ES algorithms and a non-literal algorithm argument fence at compile time where PyJWT signs with a private key, claims beyond `str` values (`exp`, `aud`) fence, errors surface as `ValueError` rather than PyJWT's `InvalidTokenError` hierarchy, and a multi-claim payload is emitted with the claims sorted by key where PyJWT emits insertion order (decode does not depend on the order; single-claim tokens are byte-identical to PyJWT's). Source: header of `src/pyscriptc/runtime/ps_jwt.c`, the [JWT guide](https://pyscriptc.pages.dev/docs/guide/jwt/).
23. The `orjson` pack lowers `orjson.dumps` and `orjson.loads` over the same C JSON writer and reader as `json`: compact `bytes` output, `OPT_SORT_KEYS` and `OPT_INDENT_2`, with the `json` subset's value shapes. The `default=` callable, every other `OPT_*` flag, `orjson.Fragment` and orjson's extended types (`dataclass`, `UUID`, `datetime`, `numpy`) fence, and errors surface as `ValueError` rather than `orjson.JSONDecodeError`. Source: `restlower/_orjson.py` and `src/pyscriptc/runtime/ps_json.c`, diffed byte for byte against the real orjson under CPython (`tests/test_pack_orjson_conformance.py`), the [orjson guide](https://pyscriptc.pages.dev/docs/guide/orjson/).
24. `@contextmanager` runs the body's code after the `yield` when the `with` exits cleanly, and re-raises the in-flight exception when the body raises, but the CPython `gen.throw` path that lets the generator catch the exception is unreachable: the manager's `__exit__` marks the frame done instead of throwing into it, so a `try`/`except` inside the generator cannot see the in-flight exception. Source: `src/pyscriptc/coro.py` (`_manager_class`).
25. A `finally` that is pending when the generator is abandoned does not run: `close()` marks the frame done and drops the pending `finally`, where CPython raises `GeneratorExit` inside the generator so its `finally` runs and its cleanup happens. A `finally` that is reached because the generator runs to completion or raises through the `try` behaves exactly like CPython's. Source: `src/pyscriptc/coro.py` (`_GeneratorKind.methods`, the `close` entry).
26. The threading surface that needs a second thread (`threading.Thread`, `threading.Condition`, `threading.Semaphore`, `threading.Event`, `queue.Queue`) is native-only: on a `wasm32` target the link is refused with a diagnostic naming the target and the runtime symbols it cannot use, because wasi-libc stubs `pthread_create` to return `EAGAIN` and its `pthread_cond_wait` traps. The `threading.Lock` primitives that need no second thread are unaffected. Source: `_refuse_unsupported_target` in `src/pyscriptc/emit/llvm/_driver.py`.
27. The HTTP client is a closed subset of `urllib.request`: only `urlopen` and `Request` lower. `urlopen` accepts `url`, `data` and `timeout`; headers ride the `Request` as a dict display with constant `str` keys and values, so runtime-built header dicts fence. `urlretrieve`, openers and proxy handling fence. The error types are synthetic `HTTPError` and `URLError` records that match through the `OSError` chain, not the full `urllib.error` class surface. Source: `src/pyscriptc/restlower/_urllib.py`, `src/pyscriptc/runtime/ps_http.c`, the [HTTP guide](https://pyscriptc.pages.dev/docs/guide/http/).
28. `https://` raises `OSError` in the compiled program: the native client speaks plaintext HTTP/1.1 only, because TLS (mbedTLS through the FFI manifest) has not landed. CPython raises nothing and makes the request. Source: `src/pyscriptc/runtime/ps_http.c`, issue [#235](https://github.com/sigilco/pyscriptc/issues/235).
29. `socket`, `ssl`, `http.client`, `http.server` and `selectors` are not lowered: an import of any of them is a `PS2001` fence naming the module. CPython provides them. Inbound servers and `http.client` keep-alive are issues [#227](https://github.com/sigilco/pyscriptc/issues/227)-[#230](https://github.com/sigilco/pyscriptc/issues/230) and [#237](https://github.com/sigilco/pyscriptc/issues/237); the event loop underneath (`epoll`/`kqueue`) is [#177](https://github.com/sigilco/pyscriptc/issues/177), which is also why `asyncio` I/O without the lowered `run`/`sleep`/`gather`/`create_task`/`wait_for` surface fences. Source: `src/pyscriptc/stdlib_queue.py`.
30. `urlopen` and `Request` are native-surface only: on the `wasm32` and `*-windows-*` targets the runtime stub raises `URLError` (an `OSError`) at run time with a message naming the target family, because WASI has no sockets and Windows needs winsock. Programs that never call `urlopen` link unchanged for those targets. Source: the stub section at the end of `src/pyscriptc/runtime/ps_http.c`.
31. On `wasm32-wasi-musl` the program is a WASI preview1 command module, and the preview1 surface is smaller than a POSIX host: there is no subprocess (`fork`/`exec` has no WASI story, so `subprocess` calls are refused at link time with a diagnostic naming the target), no `dlopen` and therefore no mix seam (`zlib.crc32` through the mix seam is refused the same way), and no island fallback (already refused for every cross target). The threading primitives that lower everywhere (`Lock`, `RLock`, `get_ident`, `active_count`, `current_thread().name`) work on the one thread a WASI program has; wasi-libc's pthread stubs never block, and `threading.Thread` is fenced by the lowerer on every target. The filesystem is preopen-only, so the wasmtime invocation must pass `--dir` or `-S dir::/path` preopens for the program to see any file; `os.getcwd` and the tempfile helpers write into whatever is preopened. `tempfile.NamedTemporaryFile` uses an `open(O_CREAT|O_EXCL)` port in `ps_osmore.c` because wasi-libc declares no `mkstemp`. The emitted entry point is `@__main_argc_argv` on wasm targets, since wasm-ld resolves a C-style `main` only through that name. Everything else is unchanged: the smoke lane proves stdout byte-identical to the native binary on the same program. Source: the wasm lane in `link_binary` in `src/pyscriptc/emit/llvm/_driver.py`, and the runtime gates in `src/pyscriptc/runtime/ps_osmore.c`.
32. On `wasm32-wasi-p2` the program is a WASI 0.2 component: the same preview1 core module wrapped by `wasm-tools component new --adapt` with the preview1 adapter pinned from the wasmtime v50.0.0 release (URL, version and sha256 recorded in `src/pyscriptc/wasm_adapter.py`; a fetched adapter whose digest does not match the pin is refused, never used). The component imports `wasi:cli/run@0.2.x` instead of the raw preview1 functions, and every constraint of divergence 31 applies unchanged. There is no thread world to spawn into on 0.2; threading arrives with the WASI 0.3 coop-threads lane, which is a separate deliverable. Generators lower through the wrap unchanged. Source: `_wrap_wasi_p2` in `src/pyscriptc/emit/llvm/_driver.py`, and `src/pyscriptc/wasm_adapter.py`.
33. On a `*-windows-*` target the program is a Win32 PE binary built by cross-compilation, and the Win32 surface is smaller than a POSIX host in ways the runtime cannot paper over: `os.path.islink` is always false and `os.lstat` follows the link instead of reporting it, because Windows has no `lstat`; path handling is Win32-flavoured, so `\` and `/` are both separators, drive letters (`C:\`) are absolute, and `os.path.join` still emits `/`; `urlopen` and `Request` raise `URLError` at run time because the HTTP client needs BSD sockets and Windows needs winsock. The remaining Windows semantics (CRLF stdout, `input()`, signals, threading) are unverified rather than claimed: the emitted binaries are never executed anywhere, in CI or otherwise. Windows is experimental cross-compilation only; native Windows compiles are not supported yet. Source: `src/pyscriptc/runtime/ps_compat.h`, `src/pyscriptc/runtime/ps_path.c` and the stub section at the end of `src/pyscriptc/runtime/ps_http.c`.
34. A generator abandoned while suspended inside a `with` block never runs the block's `__exit__`: `close()` marks the frame done without unwinding the (desugared) `try`, and dropping the frame has no cleanup, where CPython raises `GeneratorExit` inside the generator at collection time so the `with` unwinds and `__exit__` runs. A generator that leaves the `with` by resuming past the block, by returning, or by raising through it runs `__exit__` exactly like CPython, and a suspension inside the block correctly skips it. This is the `with` sibling of divergence 25. Source: `.agents/notes/2026-10-24-generator-with-suspend-decision.md`, `src/pyscriptc/coro.py` (`_GeneratorKind.methods`, the `close` entry).
