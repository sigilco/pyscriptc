title: Divergences from CPython
description: The parity contract and every numbered difference from CPython 3.14.
---

pyscriptc targets CPython 3.14.x. Parsing, probes and the compatibility oracle follow 3.14.
Compiled programs match CPython 3.14 on stdout for everything that compiles, except the numbered divergences below.
The list is load-bearing: anything not listed here is claimed identical, so a difference you find that is not listed is a bug.

Constructs pyscriptc cannot compile are not divergences.
They stop the compile with a `PSxxxx` code, and every code is in [Diagnostics](diagnostics.md).

## Parity contract

- stdout: byte-exact for every compiled call. The corpus scorer compares whitespace-stripped stdout; the nightly strict corpus A/B lane (`scripts/strict_corpus_ab.py`) compares untrimmed bytes over the visible corpus and reports every difference it finds. The nightly differential probe lane (`benchmarks/probe_lane/`) does the same for the semantic probes under `probes/` and the visible corpus, and compares each `probes/divergences/` program against the bytes its ledger row recorded.

- stderr: for a `raises` probe, only the exception name must appear. Full traceback text is not matched.
- exit code: an uncaught exception prints its name to stderr and exits 1, as CPython does. An uncaught `SystemExit` follows CPython's own rule instead: an `int` value is the exit status, a `str` value is written to stderr and the process exits 1, and no value exits 0, with no class name or traceback text printed. `raise SystemExit(<int>) from <cause>` does not compile (`PS2003`).

## The tool host and the target

The compiler runs on CPython 3.11 through 3.15 (`requires-python = ">=3.11"`); the program it emits claims CPython 3.14 (`src/pyscriptc/target.json`). The two are separate, and the split is the contract:

- The **source grammar** is the host's. The compiler parses user source with the host interpreter's `ast`, so a source the host cannot parse is a `SyntaxError` before pyscriptc sees it. Syntax newer than the host (PEP 646 `def f[*Ts]`, for example) needs a host that knows it; a 3.11 host refuses such a source where a 3.14 host lowers it.
- The **emitted semantics** are the target's. The error wording (`division by zero`), the baked `sys.version` constant, the `sys.version_info` branch folds, the typeshed version gate, the dependency resolution's Python minor and the runtime pack's stdlib tree all read `target.json`, not the host. A 3.11 host and a 3.14 host emit the same program for the same source; the canonical IR of the whole probe corpus is byte-identical across 3.11, 3.13, 3.14 and 3.15 hosts once the `cpython` stamp line is stripped (the stamp names the lowering interpreter by design, and the typed hash serializer (`pyscriptc/tirhash.py`) never emits it, so the IR hash gate is unaffected).
- The **island** mirrors the host it links. A program that embeds CPython runs the interpreter the binary carries, and `sys.executable` is the binary's own path (divergence 41 and 42 describe the embedded interpreter's version).
- The **verify oracle** is the target's minor, 3.14, and any 3.14.x patch is accepted silently: the patch of the declared target is informational, so an oracle at 3.14.10 draws no warning against a 3.14.9 target. An older oracle (3.11 through 3.13) is opt-in only (`--oracle-version 3.12`, or `PYSC_ORACLE_ANY=1`), and the run then warns that parity is meaningful only for the subset the two interpreters share. A newer oracle (3.15) is refused. The PS3001 refusal names `uv python install 3.14`, the exact fix.

Two constants are deliberately *not* target-pinned, because they describe the machine rather than the program: `sys.executable` (an environment path, which the IR hash serializer classifies as incidental) and the host's own `sys.platform`.

## Numbered divergences

Every entry has a row and a probe in `divergence-ledger.json`, regenerated by `scripts/gen_divergence_ledger.py`; a test replays each row's recorded bytes, so a divergence that is fixed or that moves is a reviewed change.

1. `int` is `i64`. Overflow aborts the process instead of growing a big int.
2. `//` and `%` by zero raise `ZeroDivisionError` matching CPython 3.14's `division by zero` (or 3.13's variant on a 3.13 host), rather than aborting the process.
3. The `str` model is mid-migration to the CPython code-point model (epic [#472](https://github.com/sigilco/pyscriptc/issues/472); this item is rewritten again when it lands). A `str` is a UTF-8 byte buffer with a code-point count and an ASCII flag, so `len`, indexing, slicing and the find/count/justify family count code points, the case family applies the full Unicode 16.0.0 mappings, and text output (stdout, text-mode files, stdin reads) is UTF-8 bytes as CPython writes it. A literal may hold any scalar code point; a lone surrogate stops the compile with `PS2005` (no UTF-8 bytes to store). `chr()` with a literal surrogate stops with `PS2005`; at run time, `chr()` with a variable surrogate code point raises `ValueError: chr() arg not in range(0x110000)` where CPython returns the surrogate character. `format` widths and precisions count code points, `repr` follows CPython's escape rules (`repr("café")` is `'caf\xe9'`), `%c` and the `c` spec take a code point, and the six is* predicates plus `isascii` decide on code points. The is* predicates that need Unicode category tables beyond the case data (`isalpha`/`isalnum` on a non-cased code point, `isspace` beyond ASCII) raise `NotImplementedError` naming the predicate and the code point. `translate`, `maketrans`, `istitle`, `isdecimal`, `isnumeric`, `isprintable`, `iscapitalize` do not compile (`PS2001`). `unicodedata` now answers over the whole code-point range (issue [#476](https://github.com/sigilco/pyscriptc/issues/476)): the general category, the combining class, the bidirectional class, the east asian width, the mirrored flag, the decimal/digit/numeric values, the decompositions, the names, the formal aliases and the four normalization forms come from the generated Unicode 16.0.0 tables, so a code point above the BMP answers as CPython does and a normalization that leaves Latin-1 no longer raises `ValueError`; `re` and `json` are separate items (4 and 5).
4. `re` is the runtime's byte-oriented backtracking subset, not CPython's `re`. `L`, `T`, `DEBUG` and unknown flag bits raise `ValueError`, `A` and `U` are no-ops, and a pattern that can loop without consuming stops with `RuntimeError` once its fuel is spent. Five or more groups are refused.
5. `json.dumps` escapes the non-ASCII text the way CPython's default does (`"café"` comes back `"caf\u00e9"`, a code point above the BMP as the surrogate pair) and `ensure_ascii=False` writes it raw as UTF-8; the reader accepts both forms, and a lone surrogate in an escape raises the runtime `JSONDecodeError` where CPython answers the decode error at the print. `json.loads(b"...")` decodes the bytes as UTF-8 first, so a malformed sequence raises the UnicodeDecodeError family like CPython's decode; CPython also reads a BOM-announced UTF-16 or UTF-32 buffer and the runtime refuses it (`JSONDecodeError`).
6. Set and `frozenset` iteration is insertion order, not CPython's hash order. Length and membership match.
7. After `for i in range(0)`, a new loop target reads as `0` instead of raising `UnboundLocalError`.
8. A subclass `__init__` that never assigns an inherited field leaves it at the zero value of its type instead of raising `AttributeError`.
9. A user exception class runs its own `__init__` on the raise (issue [#448](https://github.com/sigilco/pyscriptc/issues/448)): the raise site builds the class instance and the record carries it as its payload, so `except C as e` reads the custom fields (`e.code`) back off it, and a `raise e` over a bound handler value re-raises the record as it is. The class's own constructor arguments are the ones `__init__` takes (the builtin one-scalar shape does not apply to a user class), and the record's message is the single constructor argument, the way CPython's `BaseException.__new__` stores it. `e.args` is the exception's part: it holds the message list, not the constructor arguments, so a user exception's `args` is `("7",)` where CPython's is `(7,)` (an int), and a constructor with more than one argument has an empty message and an empty `args`. A user exception class without its own `__init__` inherits the builtin base's arity (one scalar argument) and its fields read their zero value. The probe is `probes/differential/user_exc_init.py`.
10. A classmethod body's `cls` is the compile-time class id of the class the method is defined on (an int), not a class object: `cls.attr` resolves against that class at compile time (a subclass's own-name attribute override is not seen), `cls.method(...)` and `cls(...)` are static calls against it, and using `cls` as a value (passing it on, comparing it, printing it) fences `PS2002`.
11. Some library failures surface as a different exception type: `importlib.resources.files` on a zip or missing package raises `ValueError` rather than `ModuleNotFoundError`, `shutil.copyfile` of the same path raises `RuntimeError` rather than `SameFileError`, other `shutil` and `os` failures (except `os.mkdir`, `os.makedirs` and `Path.mkdir` which raise `FileExistsError`) are `RuntimeError`, and type errors on `unicodedata` calls surface as `ValueError`.
12. `assert` is always evaluated; a compiled binary has no `-O`.
13. `x is None` compiles as `==` against `None`. Identical for `None` because it is a singleton; every other `is` on a scalar is refused.
14. `ABC`, `ABCMeta`, `Protocol`, `@abstractmethod` and `@overload` compile as plain classes and methods with no CPython runtime semantics.
15. Calls that run through embedded CPython (`subprocess.check_output`, `socket.gethostname`, `threading`, `logging`) follow the interpreter the binary links, not the pin.
16. `dotenv` compiles a closed subset of python-dotenv's parsing rules, and it differs from the library in three places. The subset: a UTF-8 BOM is stripped, blank lines and whole-line comments are skipped, an `export ` prefix is allowed, keys are bare (`KEY` alone binds `None`), an unquoted value runs to the end of the line with the ` #` comment cut and the rest right-stripped, a double-quoted value decodes `\" \\' \\ \a \b \f \n \r \t \v` and a single-quoted one only `\\` and `\'`, and a later binding overwrites an earlier one. No interpolation (`$NAME` stays literal), no multi-line values, no quoted keys, and the `stream`, `verbose`, `interpolate`, `override` and `encoding` arguments are refused. The three differences: a malformed line raises `ValueError` where python-dotenv skips it with a warning, a missing file parses as the empty document where python-dotenv searches with `find_dotenv()`, and `load_dotenv` does not overwrite a variable that is already in the environment (its `override=False` default) while still returning `True` for a document with bindings.
17. `yaml.safe_load` covers a closed YAML subset, not all of PyYAML: timestamps and sexagesimal numbers (`1:30`) raise `ValueError` where PyYAML resolves them to `date` and `int` objects, and errors surface as `ValueError` rather than `yaml.YAMLError`.
18. Plaintext `http://` is native: the compiled program makes the request itself, with no subprocess and no host `curl`. `https://` rides the system libcurl, linked at build time as a shared library (issue [#235](https://github.com/sigilco/pyscriptc/issues/235)): a program whose emitted IR reaches an `https://` URL gains libcurl's flags (resolved through `curl-config --libs` or `pkg-config libcurl`) on its link line, so the libcurl development package is a build dependency of such a program and the compile fails with a diagnostic naming the package to install when neither tool finds it (`apt install libcurl-dev` on Debian/Ubuntu, `brew install curl` on macOS, `dnf install libcurl-devel` on Fedora). `PSC_CURL_DYNAMIC=1` opts out of the build-time link; the `https://` request then raises `OSError` at run time where CPython makes the request. Peer and hostname verification stay on in every shape; there is no insecure fallback. An `http://`-only program carries no libcurl dependency. See [HTTP](https://pyscriptc.pages.dev/docs/guide/http/).
19. `generator.send(v)` on a generator that has not started ignores `v` and runs the body from the top, where CPython raises `TypeError: can't send non-None value to a just-started generator`. `None` (the priming `send`) behaves identically in both. `yield <v>` as an expression (the send receipt, issue [#437](https://github.com/sigilco/pyscriptc/issues/437)) compiles for the single-name targets `x = yield v` and `x: T = yield v`: the frame carries a `.ps_send` field and the generator a `send` method whenever the annotation's send type is not `None`, the value arrives at the resume point of the yield that asked for it, and a consumer pumping the generator byte-matches CPython (the probe `probes/differential/generator_send.py`). Every other yield-as-expression form (`x.attr = yield v`, `x[i] = yield v`, `(yield v)` inside a larger expression) stays fenced with `PS2002`.
20. `generator.throw(E)` marks the frame done and raises `E` out of the call site. CPython's "the generator catches it, execution continues" outcome is not reachable through this surface: `throw` is a separate entry point that never runs the generator's own `except` handlers. `GeneratorExit` semantics do not apply either: `close()` marks the frame done without running a pending `finally`, where CPython raises `GeneratorExit` inside the generator so its `finally` runs.
21. `yield from <subgenerator>` drains the subgenerator and discards its return value (`StopIteration.value`), where CPython's `yield from` expression evaluates to it. Statement-form `yield from` (the only form that compiles) never reads the value, so no observable program differs. A `return <value>` in a generator compiles (the value rides in the frame) but no surface reads it back.
22. The curated `pyscriptc-jwt` distribution package compiles the HMAC family only: `HS256`, `HS384` and `HS512` through `jwt.encode` and `jwt.decode` over a `dict[str, str]` payload. RS/ES algorithms and a non-literal algorithm argument stop the compile where PyJWT signs with a private key, claims beyond `str` values (`exp`, `aud`) are refused, errors surface as `ValueError` rather than PyJWT's `InvalidTokenError` hierarchy, and a multi-claim payload is emitted with the claims sorted by key where PyJWT emits insertion order (decode does not depend on the order; single-claim tokens are byte-identical to PyJWT's).
23. The curated `pyscriptc-orjson` distribution package compiles `orjson.dumps` and `orjson.loads` over the same C JSON writer and reader as `json`: compact `bytes` output, `OPT_SORT_KEYS` and `OPT_INDENT_2`, with the `json` subset's value shapes. The `default=` callable, every other `OPT_*` flag, `orjson.Fragment` and orjson's extended types (`dataclass`, `UUID`, `datetime`, `numpy`) are refused, and errors surface as `ValueError` rather than `orjson.JSONDecodeError`.
24. `@contextmanager` runs the body's code after the `yield` when the `with` exits cleanly, and re-raises the in-flight exception when the body raises, but the CPython `gen.throw` path that lets the generator catch the exception is unreachable: the manager's `__exit__` marks the frame done instead of throwing into it, so a `try`/`except` inside the generator cannot see the in-flight exception.
25. A `finally` that is pending when the generator is abandoned does not run: `close()` marks the frame done and drops the pending `finally`, where CPython raises `GeneratorExit` inside the generator so its `finally` runs and its cleanup happens. A `finally` that is reached because the generator runs to completion or raises through the `try` behaves exactly like CPython's.
26. The threading surface that needs a second thread (`threading.Thread`, `threading.Condition`, `threading.Semaphore`, `threading.Event`, `queue.Queue`) is native-only: on a `wasm32` target the link is refused with a diagnostic naming the target and the runtime symbols it cannot use, because wasi-libc stubs `pthread_create` to return `EAGAIN` and its `pthread_cond_wait` traps. The `threading.Lock` primitives that need no second thread are unaffected.
27. The HTTP client is a closed subset of `urllib.request`: only `urlopen` and `Request` compile. `urlopen` accepts `url`, `data` and `timeout`; headers ride the `Request` as a dict display with constant `str` keys and values, so runtime-built header dicts are refused. `urlretrieve`, openers and proxy handling are refused. The error types are synthetic `HTTPError` and `URLError` records that match through the `OSError` chain, not the full `urllib.error` class surface. See [HTTP](https://pyscriptc.pages.dev/docs/guide/http/).
28. `https://` raises `OSError` in the compiled program: the native client speaks plaintext HTTP/1.1 only, because TLS (mbedTLS through the FFI manifest) has not landed. CPython raises nothing and makes the request. Issue [#235](https://github.com/sigilco/pyscriptc/issues/235).
29. `ssl` and `http.client` do not compile: an import of any of them stops the compile with `PS2001` naming the module. CPython provides them. `socket` is the exception since issue [#1270](https://github.com/sigilco/pyscriptc/issues/1270): its closed blocking TCP subset lowers (divergence 77), and the parts of the module outside that subset keep the `PS2001` fence. `http.server` is the same issue's second slice: its closed loopback handler subset lowers (divergence 80), and `ThreadingHTTPServer`, `SimpleHTTPRequestHandler` and the rest of the module keep the `PS2001` fence. Inbound servers beyond the subset and `http.client` keep-alive are issues [#227](https://github.com/sigilco/pyscriptc/issues/227)-[#230](https://github.com/sigilco/pyscriptc/issues/230) and [#237](https://github.com/sigilco/pyscriptc/issues/237); the event loop underneath (`epoll`/`kqueue`) is [#177](https://github.com/sigilco/pyscriptc/issues/177), which is also why `asyncio` I/O without the compiled `run`/`sleep`/`gather`/`create_task`/`wait_for` surface is refused. `selectors` compiles as a closed subset over that loop (`src/pyscriptc/runtime/ps_select.c`, the `DefaultSelector` records over the #177 poller): `DefaultSelector`, `SelectorKey`, `EVENT_READ`/`EVENT_WRITE`, and `register`/`unregister`/`modify`/`select`/`get_key`/`close`. The subset takes a bare int fd where CPython takes a `fileobj` - the typed `socket` handle is [#229](https://github.com/sigilco/pyscriptc/issues/229), and until it lands the fd-carrying object has no type to hand over, so `sel.register(sock, events)` fences with `PS1003` naming #229. Two further shapes differ from CPython: `select()` returns `list[SelectorKey]`, not CPython's `list[tuple[SelectorKey, int]]` pairs, and `get_key` of an unregistered fd returns `None`, where CPython raises `KeyError`. `SelectorKey` carries `fd` and `events`; CPython's `fileobj` and `data` attributes stay outside the subset for the same #229 reason. When #229 lands, `register` reads the fd off the handle and the runtime records do not change. The scope decision is recorded in issue [#485](https://github.com/sigilco/pyscriptc/issues/485).
30. `urlopen` and `Request` are native-only: on the `wasm32` and `*-windows-*` targets the runtime stub raises `URLError` (an `OSError`) at run time with a message naming the target family, because WASI has no sockets and Windows needs winsock. Programs that never call `urlopen` link unchanged for those targets.
31. On `wasm32-wasi-musl` the program is a WASI preview1 command module, and the preview1 surface is smaller than a POSIX host: there is no subprocess (`fork`/`exec` has no WASI story, so `subprocess` calls are refused at link time with a diagnostic naming the target), no `dlopen` and therefore no native-to-embedded call (`zlib.crc32` through that path is refused the same way), no symbolic links (`os.symlink` and `os.readlink` are refused at link time with the same target-naming diagnostic), and no pipe or descriptor copy (`os.pipe`, `os.dup` and `os.dup2` are refused at link time with the same target-naming diagnostic; wasi-libc keeps `pipe` and `dup` out of the preview1 surface), and no fallback mode (already refused for every cross target). The threading primitives that compile everywhere (`Lock`, `RLock`, `get_ident`, `active_count`, `current_thread().name`) work on the one thread a WASI program has; wasi-libc's pthread stubs never block, and `threading.Thread` is refused on every target. The filesystem is preopen-only, so the wasmtime invocation must pass `--dir` or `-S dir::/path` preopens for the program to see any file; `os.getcwd` and the tempfile helpers write into whatever is preopened. `tempfile.NamedTemporaryFile` and `tempfile.mkstemp` use an `open(O_CREAT|O_EXCL)` port (`ps_mkstemp`) because wasi-libc declares no `mkstemp`; the file lands in whatever preopen holds the temp directory. The emitted entry point is `@__main_argc_argv` on wasm targets, since wasm-ld resolves a C-style `main` only through that name. Everything else is unchanged: the smoke lane proves stdout byte-identical to the native binary on the same program.
32. On `wasm32-wasi-p2` the program is a WASI 0.2 component: the same preview1 core module wrapped by `wasm-tools component new --adapt` with the preview1 adapter pinned from the wasmtime v50.0.0 release (URL, version and sha256 recorded in `src/pyscriptc/wasm_adapter.py`; a fetched adapter whose digest does not match the pin is refused, never used). The component imports `wasi:cli/run@0.2.x` instead of the raw preview1 functions, and every constraint of divergence 31 applies unchanged. There is no thread world to spawn into on 0.2; threading arrives with the WASI 0.3 coop-threads lane, which is a separate deliverable. Generators compile through the wrap unchanged.
33. On a `*-windows-*` target the program is a Win32 PE binary built by cross-compilation, and the Win32 surface is smaller than a POSIX host in ways the runtime cannot paper over: `os.path.islink` is always false and `os.lstat` follows the link instead of reporting it, because Windows has no `lstat`; path handling is Win32-flavoured, so `\` and `/` are both separators, drive letters (`C:\`) are absolute, and `os.path.join` still emits `/`; `os.symlink` makes file links only and `os.readlink` raises `RuntimeError` at run time, because Windows has no CRT `readlink`; `urlopen` and `Request` raise `URLError` at run time because the HTTP client needs BSD sockets and Windows needs winsock. The remaining Windows semantics (CRLF stdout, `input()`, signals, threading) are unverified rather than claimed: the emitted binaries are never executed anywhere, in CI or otherwise. Windows is experimental cross-compilation only; native Windows compiles are not supported yet.
34. Only refusals in modules the compiled tree's import graph reaches stop a compile with dependency source roots (`PyPI` pure wheels, issue [#424](https://github.com/sigilco/pyscriptc/issues/424)). In a program the graph starts at the entry module; in a library package it starts at every module, because any of them can be the consumer's import target. The rule rests on CPython's import-time side effect rule: a module body runs once, at the import that reaches it, and never otherwise, so a dependency module the tree never imports never runs and a refusal inside it cannot change what the compiled program does. Such a module is pruned (named on stderr as a note, not compiled) or kept in the export table without compiling when an unreached program module imports it. A reached dependency refusal stops the compile with its code and the distribution that ships it. The reach walk is static and name-based, so a dynamic import (`importlib.import_module`, `__import__`, both refused) never extends it. The program's own modules keep the whole-tree rule: a refusal in one of them always stops the compile. CPython runs every module whose import appears anywhere in the executed call graph, so a program whose entry reaches that module through a dynamic import behaves differently: CPython refuses at run time or succeeds through the import, where the compile succeeded without the module's code.
35. The `__getattr__` hook compiles for unknown-name reads only, and only for one shape: a plain instance method `def __getattr__(self, name: str) -> T`. The read compiles as a direct call of the first MRO definer with the attribute name as a compile-time constant, and the hook's declared return type must cover the read site exactly (`PS4204` otherwise). Everything else in the dynamic attribute protocol stays refused at the definition site: `__setattr__`, `__getattribute__`, `__get__`, `__set__` (`PS4201`), `__delattr__` (`PS4202`), `__del__` (`PS4203`), and a `__getattr__` in any other shape (a decorator, a different parameter list). Where CPython dispatches a missing attribute through `__getattr__` on any shape, or an attribute write or deletion through the protocol, the compile stops instead. An unguarded read of a name the hook itself reads recurses to no limit in the binary where CPython raises `RecursionError`. Writes (`__setattr__`) are still refused. Issue [#434](https://github.com/sigilco/pyscriptc/issues/434).
36. The shortest float spelling sometimes carries an exponent form CPython does not use at that magnitude: `10.0` prints `1e+01` where CPython prints `10.0` (`100.0` prints `1e+02`). The shortest round-trip search accepts `%g`'s exponent spelling before CPython's fixed-notation preference kicks in, so the value is exact and the bytes differ for whole floats whose shortest spelling picks an exponent. Values whose shortest spelling is fixed-notation (`0.5`, `16.1`, `0.1`) are byte-identical.
37. A `round(x, n)` call whose constant `ndigits` is outside 0 to 8 stops the compile (`PS2003`) where CPython rounds for `-8 <= n <= 20`. A variable `ndigits` outside the range raises `ValueError: round ndigits is out of the supported range` at run time. In range, `round(x, n)` rounds the exact binary value of `x` the way CPython's dtoa path does (`round(2.675, 2)` is `2.67`).
38. `newline=` is refused on `open`, so text-mode reads always apply the default universal-newline translation (`\r\n` and `\r` read as `\n`); a program that needs CPython's `newline=""` (no translation) or a specific newline spelling cannot compile the call. `encoding=` compiles only as a str constant from `{utf-8, ascii, latin-1}` and their usual spellings (case folded, `_` read as `-`, `us-ascii`, `iso-8859-1`); the text default is UTF-8 whatever the host locale says, ascii and latin-1 are honored by the runtime (one byte per code point, `UnicodeEncodeError` or `UnicodeDecodeError` outside the range), and any other codec is a PS2001 fence. `encoding=` on a binary mode is refused. CPython accepts any encoding object and honors it. A third positional (`buffering`) and the other `open` keyword arguments are refused.
39. `int(text, base)` compiles for bases 2 to 36 and matches CPython's read and messages (the leading prefix sits behind the sign, base names check like CPython's, the surrounding-whitespace strip takes the Unicode space set, and the underscore digit separator follows CPython's rule: one `_` between two digits, never at an end, never doubled), with the i64 ceiling of divergence 1. Base `0` and out-of-range base constants stop the compile (`PS2003`), where CPython accepts both (base 0 prefixes off the text). One message detail stays open: an invalid literal in the `bytes` form is reported with the `str` repr (`invalid literal for int() with base 10: '1x'`) where CPython writes the `bytes` repr (`b'1x'`), because the runtime reads both forms through one buffer ABI that does not carry the str/bytes distinction.
40. `subprocess.run` takes `capture_output=`, `text=` and `check=` as bool literals: `check=True` raises the `check_call` stand-in `RuntimeError` on a non-zero exit where CPython raises `CalledProcessError` carrying the cmd and returncode. `text=True` (or an `encoding=` name) decodes the captured streams through the runtime's CPython-exact decoder (`utf-8`/`ascii`/`latin-1` with `strict`/`replace`/`ignore`/`backslashreplace`), so the record's `stdout`/`stderr` are str like CPython's text-mode record; the default bytes path is unchanged. `cwd=` compiles as a str, Path or None; `input=`, `shell=` and the remaining popen keyword arguments are refused (`timeout=` is its own entry, divergence 71).
41. Fallback mode (`compile --fallback=cpython`, alias `--island`) routes a function pyscriptc cannot compile to embedded CPython: that function's source segment plus the module's top-level imports and module-global initializers are exec'd once inside the binary (so a global initializer runs again in the embedded interpreter; for a deterministic initializer like `Path.home() / x` the value matches, and a change to a global made there is never visible to native code), and every call to it crosses into the embedded interpreter. Under fallback mode an annotated function that accumulates an unbounded `int` also runs there (issue [#677](https://github.com/sigilco/pyscriptc/issues/677)): a conservative static check finds the growth shape (a `*=`, `<<=`, `**=` in-place update, or the loop-carry assign `name = name <op> anything` with a multiplying operator) and plans that function for the embedded interpreter instead of letting the native i64 overflow of divergence 1 abort it, so an annotated program keeps CPython's arbitrary-precision result where the same function compiled natively would not. A single `name = name ** k` assign with a literal exponent of at most 62 and no loop in the body stays native. Values cross one way per call: scalars, `str`, `bytes` and lists of scalars by value (a list is copied, so a change made there is not visible to native code), `dict` and everything else as an opaque handle usable through attribute reads, item reads, further calls and `str()`/f-string formatting, never by native operators. No object identity survives a crossing. A function running in the embedded interpreter that calls a compiled sibling stops the compile with a diagnostic naming both functions, where CPython would run the call. A class definition that pyscriptc cannot compile (`@attrs.define`, `@dataclasses.dataclass(frozen=True)`, any decorator the native dataclass form does not take, class keywords, a class-body statement) or whose method bodies cannot compile is routed the same way (issue [#628](https://github.com/sigilco/pyscriptc/issues/628)): the class leaves the native class table, the embedded interpreter defines it, and every compiled function that names it is routed there too. A native class method that still uses that class reaches it through the handle path: an instance is a call on the class name, a class-level attribute read goes through the handle path, and an attribute write from compiled code stops the compile because values cross one way. Functions and classes routed there run under the host CPython (3.14.x), not the compiled runtime.
42. With fallback mode on, the module top level is all-or-nothing: the synthesized entry body is probed like a function, and a refused probe (a module-level statement the subset does not take, an unannotated `yaml.safe_load` result, a `Path` global) plans the whole top level for the embedded interpreter instead of stopping the compile. The binary's `main` seeds the embedded interpreter with the module's own source text, exec'd once with `__name__ = "__main__"` (the script's main guard fires there exactly once) and `__file__` set to the compiled source path; `sys.argv` mirrors the process argv, so `sys.argv[0]` is the binary path where CPython shows the script path. `raise SystemExit(status)` out of the body delivers the process status (an int becomes the exit code, a str prints to stderr and exits 1), and any other uncaught exception surfaces as its own type and message with exit 1, matching CPython's shape but not its traceback bytes. Annotated scalar globals the top level binds (`LABEL: str = os.environ.get(...)`) unbox once at init into native shadow slots, so typed native functions read the embedded interpreter's initial value; a later rewrite of the global there is never visible to native code, and a native write to a global owned there stops the compile naming the global. Unannotated top-level globals stay in the embedded interpreter only. The native entry never runs when the top level is routed there: every function rides the seed, and it runs under the host CPython (3.14.x).
43. `argparse` `type=Path` options compile to a native `Path` in the namespace, but the namespace has no None slot, so an absent option cannot be None. A `type=Path` option without `required=True` or a str default stops the compile (`PS2003`), and a default is converted to a `Path` at parse time. `parse_args` takes `None`, a list of str, or an Optional list; the list form skips `sys.argv`.
44. A local that is first bound to a value and later assigned `None` (or an Optional call result) in a branch is not widened to Optional. The first binding fixes the type, so `lp = Path(x)` followed by `lp = find_latest()` stops the compile with `PS1003`, and `lp is None` on a plain `Path` stops with `PS2004`. The typed form `lp: Optional[Path] = None` compiles. Narrowing through `is None` and `is not None` guards combined with `and`, `or`, conditional expressions, early exits and loop bodies does compile.
45. These shapes are refused after the mechanical-delta pass, each as its own PS code: `set(d)` and `list(d)` over a dict (PS2002, the set kind takes a list of int or str), `sorted(paths)` over `Path` elements (PS2003), `Path.open("rb")` (PS2001), `collections.abc.Sequence` annotations (PS1104), class-body values the compiler cannot compute (PS1204; a `name = <constant>` or `name: T = <constant>` class attribute compiles and reads through the class and its instances, and so does a value the compiler computes (a call to a lowered function, a container literal, a comprehension, a name bound at module scope) stored in a runtime slot keyed `C.<name>` and initialized at module init, where CPython computes it in the class body; a value with no slot form, a tuple or a float or a multi-target assign, still fences), module-level list-of-dict tables (PS1106, dict values are not heterogeneous), and a module-level `Path(__file__).resolve().parents[n]` constant (PS1001).
46. Under fallback mode for a whole program, the compile stages the program directory's non-Python files beside the binary (`<binary dir>/pyscriptc-data/<program name>/`, the exact compile-time bytes) and rebases the module origins and `__file__` of the embedded interpreter's finder onto that tree, so `Path(__file__).parent / "data.json"` reads the staged copy after the output is relocated and the source tree is gone. Lookups that leave the program directory (`Path(__file__).parent.parent / "x"`, absolute paths) are not staged and still resolve against the compile-time path: with the source tree absent they raise `FileNotFoundError` where CPython reads the real file. A single-file fallback compile stages nothing and keeps the compile-time `__file__` (the same restriction divergence 42 documents). Issue [#665](https://github.com/sigilco/pyscriptc/issues/665).
47. `os.walk(top)` is a materialized list of the `(dirpath, dirnames, filenames)` triples in CPython's topdown pre-order, so the visit order and the rows match a CPython walk over the same tree read in the same `readdir` order. The walk is computed before the loop body runs, so a body that edits `dirnames` does not prune the walk where CPython honours the edit; `topdown=`, `onerror=` and `followlinks=` are refused (`os.scandir` and the other `os` names outside the fixed rows keep their `PS2001`). `json.load(fp)` reads the whole handle and reuses the `json.loads` annotation path: a missing result annotation stops the compile (`PS1001`) where CPython returns an untyped value, and a decode failure raises the runtime `JSONDecodeError` (a `ValueError` subclass, so `except ValueError` catches it too) with the runtime's own message, not CPython's `Expecting value: line 1 column 1 (char 0)` wording. `json.dump(obj, fp)` serializes through the same `json.dumps` subset and writes the handle with one call, so the bytes are the `dumps` bytes (no trailing newline); the closed dumps keyword set (`indent`, `sort_keys`, `ensure_ascii=True`) rides along and any other keyword stops the compile (`PS2003`). `time.perf_counter` and `time.monotonic` read the monotonic clock as a float.
48. A `--embed-python=bundle` output carries a trimmed runtime: the standard library travels as the safe-trimmed zip (test, idlelib, tkinter, turtledemo, ensurepip, `pydoc_data` and `__phello__` are out), the pack interpreter's own `site-packages` tooling (pip) is not bundled, and the unversioned `libpython3.X.so` name of a bundled Linux runtime is a symlink to the versioned library, not a second copy. A program that imports a trimmed tree stops the compile closed (`PS4301`) where CPython imports it; a bundled program that calls `pip` at runtime gets the same `ModuleNotFoundError` a CPython interpreter without pip would. Issues [#709](https://github.com/sigilco/pyscriptc/issues/709) and [#885](https://github.com/sigilco/pyscriptc/issues/885).

49. The program island carries a precompiled code cache next to the embedded sources (issue [#782](https://github.com/sigilco/pyscriptc/issues/782)): the compiler marshals every program unit's code object at compile time, zlib-compresses the entries into one blob, and the seed's loader unmarshals a module on its first import instead of compiling it (a 523 ms to 333 ms `--version` on yt-dlp). The cache is guarded, not trusted: each entry names the compiling interpreter's `.pyc` magic number and the source's sha256, the loader re-checks both at run time against the interpreter that runs the binary and the embedded text, and any mismatch (a binary moved to a different CPython build, a corrupted blob) falls back to compiling the source, so behavior never differs - only start time. A cached program answers CPython byte for byte; traceback frames name the same `co_filename` either way. Source: `program_island_source` and `_module_code_entry` in `src/pyscriptc/boxed.py`, `ps_island_codecache` in `src/pyscriptc/runtime/ps_island.c`, and `tests/test_island_code_cache.py`.

50. A module-scope container bound without an annotation (`xs = [...]`, `d = {...}`, `s = {...}`) in a script is a compile-time constant: every read re-builds the literal, so the name has no object identity. Mutating it through a method call (`xs.sort()`, `d.update()`, `s.add()`), an item or slice store (`xs[i] = v`), or a copy-on-alias bind (`ys = xs`, `x = y = xs`) stops the compile with `PS2002` naming the annotation fix: annotating the name (`xs: list[int] = ...`) gives it a global slot and CPython identity. Two paths still read copies where CPython aliases: passing the name to a function hands the callee a fresh container, so a callee that mutates its parameter leaves the module value unchanged, and `ys = xs[i]` binds a copy of the element, so a mutation through `ys` is not shared.
51. `x += ys` and `x *= n` on a list desugar to a fresh-concat rebind, not CPython's in-place `__iadd__`/`__imul__`. The rebound name's own value is right, but a second name bound to the same list keeps the old object where CPython mutates the shared one.
52. `itertools.tee(xs)` and `tee(xs, 2)` return a pair of eager `list` copies of the materialized source (`restlower/_itertools.py`), so later mutation of one copy does not affect the other and `next` is not defined on them; CPython returns two lazy iterators that share an underlying buffer. `itertools.batched(xs, n)` yields lists of elements (a short last list when the length is not a multiple of `n`) rather than tuples, because the `batched` subset is defined over lists (a one-field tuple now lowers, issue [#1314](https://github.com/sigilco/pyscriptc/issues/1314)). Issue [#490](https://github.com/sigilco/pyscriptc/issues/490).

53. A class decorator other than `@dataclass` is erased: the class lowers undecorated (fields, methods, constructor and every read of it unchanged) and the decorator call never runs. CPython applies the decorator to the class object after the body executes, so side effects the decorator has (a registry write, a flag, a returned replacement class) are missing in the binary. Every decorator spelling other than the single `@dataclass` form takes the erase; the compile prints a `note: PS3099 ...` line on stderr and still succeeds, and the binary runs with the class's own value semantics. Under `--fallback=cpython` the class keeps the decorator: it runs through embedded CPython with the wrap applied. Issue [#732](https://github.com/sigilco/pyscriptc/issues/732).

54. A method decorator or module-function decorator outside the closed set that does not synthesize behavior is erased: the function lowers undecorated and the decorator call never runs. CPython replaces the attribute (or the module name) with whatever the decorator returns, so side effects the decorator has (a registry write, a flag, a wrapper with different call semantics) are missing in the binary. A decorator stack that carries a behavior-synthesizing member (`functools.lru_cache`, `functools.cache`, `functools.wraps`, `functools.singledispatchmethod`) never takes the erase: the stack would lower undecorated and the synthesis would be lost with it, so it keeps its fence (`PS1201` for a method, `PS2006` for a module function). The closed set (`property`, `staticmethod`, `classmethod`, `contextmanager`, the erased typing names) keeps its existing lowering. The compile prints a `note: PS3099 ...` line per erased decorator and still succeeds. Under `--fallback=cpython` the decorated definition keeps the decorator: it runs through embedded CPython with the wrap applied. Issue [#732](https://github.com/sigilco/pyscriptc/issues/732).

55. The `uuid` subset covers `uuid4()`, `uuid1()`, `uuid5(namespace, name)` and `UUID(text)`. `uuid4` and `uuid1` draw their random bytes from the host entropy source and set the version and variant bits the way CPython does, so the shape, the version nibble and the variant bits match but the values differ from CPython's by construction. `uuid5` hashes the namespace bytes and the name bytes with SHA-1 exactly as CPython does, so `uuid5` and `UUID` are byte-identical to CPython's. `UUID` is not lowered as a class: the call returns the canonical text, so `str(UUID(text))` reads the way CPython's does, and the `.hex` attribute of a lowered uuid call is the canonical text without the dashes (what CPython's `UUID.hex` holds). The `.int`, `.urn` and `.bytes` forms are refused (`PS2001`), and `uuid.UUID` as a parameter or return annotation is refused (`PS1106`) because the lowered value is text, not a class instance.
56. The `binascii` subset covers `unhexlify(text)` and `hexlify(data)`. Both are byte-identical to CPython's for ASCII hex, including the error cases: an odd-length hex string and a non-hex character raise `ValueError`, which is what CPython's `binascii.Error` reads as at an `except (ValueError, ...)` handler (`binascii.Error` itself is a `ValueError` subclass). `hexlify` takes bytes and returns bytes, as CPython's does; a `str` argument is refused at compile time (`PS1003`) where CPython raises `TypeError`. Every other `binascii` name is refused (`PS2001`).

57. The `shlex` subset covers `split(text)`, `quote(word)` and `join(words)`. `split` runs CPython's POSIX-mode lexer, so the words match CPython's byte for byte for the quoting, escaping and comment rules; the `comments` flag must be a constant bool (a variable is refused with `PS1003`), where CPython reads it at run time. An unterminated quote and a trailing backslash raise `ValueError`, as CPython's do. `quote` leaves a word alone when it holds only the characters CPython's safe set holds and wraps it in single quotes otherwise, spelling an embedded single quote `'"'"'`; `join` spaces the quoted words. The `shlex` class itself, the `posix` flag and the `punctuation_chars` mode are refused (`PS2001`).

58. The `secrets` subset covers `token_hex(n)`, `token_bytes(n)` and `randbelow(n)`. The bytes come from the host entropy source (`/dev/urandom`), the source CPython's `SystemRandom` reads through `os.urandom`, so the shapes match CPython's but the values differ by construction. `token_hex` returns the lowercase hexadecimal text of `n` random bytes (two digits per byte), `token_bytes` returns the bytes, and `randbelow` returns an int in `[0, n)` drawn the way CPython's `SystemRandom._randbelow` draws it: `n.bit_length()` bits at a time, redrawn while the draw is out of range. `n` is a constant int (a variable is refused with `PS1003`) and defaults to CPython's 32 bytes when omitted; `randbelow(0)` raises `ValueError`, as CPython's does. Every other `secrets` name (`choice`, `randbits`, `token_urlsafe`, `compare_digest`, `SystemRandom`) is refused (`PS2001`).

59. The island plan is conservative past the module that forced it: once any import in a module is routed to embedded CPython, the module's whole top level plans there (divergence 42) and every function whose body names an island-planned import or an unannotated value reaching one is planned there too, transitively through calls. On a real Flask-plus-LLM backend this compounds: 41% of its definitions pass the per-definition check in isolation, but the plane map routes 100% of them to the island because untyped imports at the module top level demote everything below them (the `assess --json` `planeMap.demotedBy` names the function that pulled each demotion). No compiled code runs unless the forced imports are moved behind a typed boundary or routed out of the compiled tree. The program still builds and runs there: the island is the route for code the subset cannot lower, not a failure, and it costs interpreter speed on the island plane plus a marshalling cost on every native-island crossing ([Libraries and fallback mode](../guide/libraries.md#the-two-planes)).

60. `math.factorial(n)` follows divergence 1: `int` is `i64`, so the factorial past `20!` raises `OverflowError` where CPython grows a big int. Every other integer helper (`gcd`, `lcm`) stays in range the way CPython's does for the same inputs; the domain errors (`factorial(-1)` is `ValueError`) match CPython exactly.
61. Float text output is shortest-round-trip without CPython's fixed-exponent rule: a value CPython prints as `180.0` prints as `1.8e+02` here. Values CPython also spells in exponent form byte-match, and every `%.17g`-style numeric comparison is unaffected; only exact `print` text near CPython's exponent crossover can differ.
62. `struct.calcsize` and `struct.unpack_from` lower only with a string-literal format that opens with an explicit byte-order prefix (`<`, `>`, `!` or `=`); `calcsize` folds to an int constant at compile time and `unpack_from(fmt, buffer, offset=0)` takes a `bytes` buffer and an `int` offset (negative offsets count from the end, as in CPython). A computed format (`PS2001`), the native `@` default and an unprefixed format (`PS2001`, native alignment is not lowered), `pack_into`, `iter_unpack`, `Struct` and `error` stay refused. Like `struct.unpack`, `unpack_from` returns a `list`, not a tuple, and a buffer too short for the format raises `ValueError` (`struct.unpack_from buffer is too small`) where CPython raises `struct.error`. Issue [#489](https://github.com/sigilco/pyscriptc/issues/489).
63. The `random` subset runs one module-level CPython-compatible Mersenne Twister: `random.seed(int)` seeds it with `init_by_array` over the int's little-endian 32-bit limbs, and every draw consumes the stream the way CPython 3.14's `random.py` does, so a seeded program prints the same numbers as CPython (the differential probe `probes/differential/random_surface.py` byte-compares them). `seed()` with no argument is nondeterministic, as in CPython, and `seed` takes an int only (no `version=`, no str, bytes or float seeds). The subset covers `random`, `randint`, `randrange`, `uniform`, `getrandbits`, `choice`, `shuffle`, `randbytes(n)`, `sample(population, k)`, `choices(population, k=n)` and `choices(population, weights=w, k=n)`, and the draws `gauss`, `normalvariate`, `lognormvariate`, `expovariate`, `triangular`, `gammavariate` and `betavariate`. `population` is a list (a str, tuple or range is refused with `PS1003`), `weights` is a `list[int]` or `list[float]`, and `choices` takes `weights` and `k` as keywords. Integer weights are accumulated in 64 bits and compared as floats, where CPython compares exact ints, so cumulative weights beyond 2**53 can pick a different index. `lognormvariate` returns `inf` on overflow where CPython raises `OverflowError`. `sample` has no `counts=`, `choices` has no `cum_weights=`, and the `Random` and `SystemRandom` classes plus `vonmisesvariate`, `paretovariate`, `weibullvariate`, `binomialvariate`, `getstate` and `setstate` are refused (`PS2001`).

64. The `pyscriptc_arrow` FFI adapter (`--ffi packaging/adapters/pyscriptc-arrow/ffi.toml`, issue [#1209](https://github.com/sigilco/pyscriptc/issues/1209)) carries the primitive fixed-width Arrow dtypes only: int32, int64, float32, float64, bool and utf8. `array_get` and `array_sum` widen every numeric element to double, so an int64 value above 2**53 loses integer precision where CPython-level int arithmetic stays exact, and an int32 value above the f64 mantissa reads rounded. The Arrow IPC wire form is a one-column record batch named `v` whose top level is a struct (the wire format requires it), so a stream PyArrow produced with a multi-column or differently named schema refuses with `ValueError` instead of projecting a silent subset; `stream_read` returns `list[dict[str, str]]` whose values are the element's own text (ints decimal, floats `%g`, bools `True`/`False`), not typed values. Every other Arrow type (nested types, dictionaries, unions, timestamps, extension metadata, decimal) is the honest fence: the thunk refuses the dtype word with `ValueError` naming the six supported constants, never a silent cast. The adapter has no `__arrow_c_array__`/`__arrow_c_stream__` capsule protocol in-process: the exchange with a live Arrow implementation goes over the wire bytes (`export_array`/`import_stream`), and a consumer under CPython opens them with `pyarrow.ipc.open_stream`.
65. The `statistics` subset (`mean`, `fmean`, `median`, `median_low`, `median_high`, `mode`, `variance`, `pvariance`, `stdev`, `pstdev`, `quantiles` with the default exclusive method and `n` in `{2, 4, 8}`) takes a `list[int]` or `list[float]`; every other `statistics` name is refused (`PS2001`) and other container shapes are refused (`PS1003`). The functions never mutate the caller's list. Two seams come from CPython's exact-rational implementation (`statistics` converts every number to a `Fraction` and converts the result to float at the end) against the i64/double runtime: `stdev` and `pstdev` differ from CPython by one ulp on a minority of datasets (CPython's correctly-rounded square root needs `math.isqrt` of a big integer), and the mean/median/variance family over `list[int]` returns `float` where CPython returns `int` (the mean of an exactly divisible int dataset, the median of an odd-length one, a variance whose exact fraction is integral): the value is equal, the `repr` is not, so `print(statistics.mean([1, 2, 3]))` prints `2.0` where CPython prints `2`. Over `list[float]` the mean/median/variance family folds in double arithmetic, so a minority of datasets round differently from the exact-rational path. `mode` takes `list[int]` only (a `dict[int, int]` count; float keys are outside the subset, `PS1003`), breaks ties the way CPython does (the first key to reach the top count), and `quantiles` takes `n` as a constant int. See divergence 61 for the float spelling rule that can also move a `print` of a whole float.

66. `csv.DictReader` returns a materialized `list[dict[str, str | None]]` where CPython returns a lazy iterator: the rows are all parsed before the loop body runs, so a loop body that mutates the source lines does not see the edit, and the reader cannot be resumed after `list()` or a second `for` (CPython's iterator is spent the same way, so a fresh `DictReader` call is the fix either way). Two row-shape differences ride along: a record longer than the header raises `ValueError: dict reader has more fields than fieldnames` at run time where CPython stores the extra fields under the `None` restkey (a `None` key and a `list[str]` value are outside the row dict's type), and `restkey=`/`restval=` are refused (`PS2003`) where CPython re-keys or refills the row. Blank records are skipped like CPython skips them. The writer matches CPython's excel dialect byte for byte, including the `\r\n` terminator, the minimal quoting and the empty-text restval for a missing field. Issue [#488](https://github.com/sigilco/pyscriptc/issues/488).

67. An island binary that links the build host's libpython is refused at the end of the compile (`PS4304`): the audit reads the linked artifact's dynamic dependencies (`otool -L` on Mach-O, `readelf -d` on ELF) and a reference to the host interpreter's library, reached by absolute path or through an absolute runpath, fails the build with that path in the message. The binary would run on the build machine and break on a target without that Python, so the build output says so before the artifact is shipped. `--embed-python=bundle` produces a relocatable binary instead, and `--allow-host-libpython` (or `[tool.pyscriptc.island] allow_host_libpython = true`) accepts the host link on purpose and warns instead. A native binary links no libpython and is unaffected.
68. The process-control surface (`os.kill`, `os.killpg` over the `ps_os_kill` runtime helpers, plus the `signal` module's POSIX constants `SIGKILL`, `SIGTERM`, `SIGINT`, `SIGCONT`, `SIGUSR1`, `SIGUSR2`) is POSIX-only. The error translation follows CPython's errno mapping exactly (`ESRCH` raises `ProcessLookupError`, `EPERM` raises `PermissionError`, everything else the plain `RuntimeError` stand-in), so a kill probe is byte-identical to CPython 3.14 on the host (the differential probe `probes/differential/os_kill_signal.py` byte-compares stdout, stderr and the exit code). On `wasm32-*` the call is refused at link time with the target-naming diagnostic (WASI has no process identifiers, and its `signal.h` errors out without the emulation macro), and on `*-windows-*` targets the runtime helpers do not compile (Windows has no POSIX `kill`; the process handle spelling is `TerminateProcess`), so a kill call stops the cross compile where CPython would run it. The `signal` module carries the constants and the native handler surface (divergence 92); the rest of the registration API (`signal.getsignal`, `signal.alarm`, `signal.set_wakeup_fd`, `signal.raise_signal`, the `Signals` enum) stops the compile with `PS2001`, because a native binary has no Python handler table to read back from; CPython registers the handler and delivers asynchronously. Issue [#1244](https://github.com/sigilco/pyscriptc/issues/1244).

69. The archive read surface (`tarfile.open`, `zipfile.ZipFile`) reads a tar as raw 512-byte ustar blocks and a zip by walking its central directory, so `r:gz` tars and ZIP_DEFLATED members read through zlib and raise `RuntimeError` on a build without it; the `r:bz2` and `r:xz` tar modes compile and then raise `RuntimeError` at run time, where CPython reads bzip2 and lzma through its own modules (`BZ2File`, `LZMAFile`). The runtime raises `KeyError` where CPython's `tarfile` does for a missing `extractfile` name, but the message wording is the runtime's (`filename not found in the archive` against CPython's quoted spelling). `extractall` writes every file with the process umask and does not preserve the archive's file modes, mtime or ownership, where CPython's `extractall` keeps them by default (CPython's own `data` filter already refuses the dangerous ones). Only pax headers of the mtime/name/path shape are honored; exotic extended-header records a hand-built archive might carry are ignored.

70. Class dispatch is static, so a slot annotated with a class only accepts a value of that exact class. The one carve-out is a nominal subclass that adds no instance field: a slot annotated with a base class accepts a value of a subclass declared in the same compile, and the slot keeps the concrete class, so the overridden method answers the subclass's body (the differential probe `probes/differential/covariant_return.py` byte-compares it). The carve-out is narrow on purpose: a subclass that adds a field keeps the `PS1003` fence (the fence names the field, because the base's slot cannot hold the wider layout), a def whose returns split over two subclasses proves no concrete class and keeps the fence at its return sites, and a subclass value passed to a base-annotated parameter keeps the `PS1003` fence (the callee's body dispatches on the annotation's class, so the call would answer the base's body where CPython answers the subclass's). CPython dispatches on the value's real class everywhere, so a base-annotated parameter that receives a subclass answers the subclass's method there and the base's method here. Issue [#1243](https://github.com/sigilco/pyscriptc/issues/1243).
71. The `subprocess.run(timeout=)` path raises `subprocess.TimeoutExpired` with CPython's exact message (`Command '['sleep', '5']' timed out after 1 seconds`) and the class matches through CPython's parent chain, so `except subprocess.TimeoutExpired` catches it and `except TimeoutError` does not (CPython's `TimeoutExpired` derives from `SubprocessError`, not from the builtin `TimeoutError`). The exception record carries the code and the message only, so the attributes CPython's `TimeoutExpired` holds (`cmd`, `timeout`, `output`, `stdout`, `stderr`) are not readable and `e.args` holds the message list instead of CPython's `(cmd, timeout)` pair. The timeout itself is a compile-time number literal: a computed timeout fences with `PS2003` where CPython reads it at run time, and a timeout at or below zero fences too (CPython raises before the child starts there). Text mode is the `subprocess.Popen[str]` annotation (or the inferred type of a `text=True` call): `proc.stdout.read()`, `readline()` and `for line in proc.stdout` answer decoded `str` (UTF-8, `\r\n` and `\r` translated to `\n`) and `proc.stdin.write(s)` answers the character count. The fences: `shell=`, `encoding=`, `errors=` and every other spawn keyword stop the compile with `PS2003`; `env=` takes a `dict[str, str]` (a `PS1003` otherwise) and `start_new_session=`, `text=` take a `True` or `False` literal; the text-mode read takes no count (`read(n)` is characters there and a byte read could split a UTF-8 sequence, so only the read-all form lowers) and a text-mode `readline()` translates a lone `\r` inside the line but does not end the line at it; the `wait(timeout=)` bound is a compile-time number literal (a computed bound stops the compile with `PS2003`, the rule `subprocess.run(timeout=)` already set); the `read(n)` count is an int literal for the same reason; a stream that was not piped answers a handle whose read or write raises `ValueError` at run time, where CPython answers `None` for the stream and the read on it raises; a `Popen[bytes]` handle is the default and `Popen[str]` the text one; and the `Popen` handle is native-only, so on `wasm32-*` the call is refused at link time with the subprocess symbols (WASI has no subprocess story, the same refusal `subprocess.run` gets) and on the mobile targets it fences at compile time with the mobile guard (an app sandbox has no fork/exec, the same fence `subprocess.run` gets). The differential probes `probes/differential/subprocess_popen.py` and `probes/differential/subprocess_popen_env.py` run the same program on both sides and the lane byte-compares stdout, stderr and the exit code.

94. `argparse` subparsers (issue [#1346](https://github.com/sigilco/pyscriptc/issues/1346)) share one namespace that has no absent slot, the same family as divergence 43. Reading an attribute of a subcommand the command line did not choose answers that argument's default (`""`, `0`, `0.0`, `False` or the declared `default=`), where CPython raises `AttributeError` because the namespace only carries the chosen subcommand's arguments. The dest of an `add_subparsers(dest=...)` without `required=True` reads `""` when no subcommand is given, where CPython reads `None`. A program that guards the read on the dest (`if args.cmd == "run":`) behaves the same. The surface is one `add_subparsers` call per module, one level deep (a nested `add_subparsers`, a second holder and the `title`, `help`, `metavar`, `description` and `parser_class` keywords stop the compile with `PS2003`), and `add_parser` takes a name and `help=` only (`aliases=`, `description=` and the other parser keywords stop the compile with `PS2003`). A parser that registers its own positionals and a subcommand fills the positionals first, where CPython follows the registration order. The error paths and the help of each level are byte-identical to CPython (usage block, `prog: error: ...` prefix with the subcommand name, exit 2): `probes/differential/argparse_subparsers.py` and `probes/differential/argparse_subparsers_optional.py` compare them, and `probes/divergences/d94_argparse_subparser_namespace.py` shows the namespace difference.

95. `argparse` `nargs=` (issue [#1373](https://github.com/sigilco/pyscriptc/issues/1373)) follows CPython's `_parse_known_args`: the positionals consume the argument pattern in registration order with the same greedy matching, so `nargs` of `"?"`, `"*"`, `"+"`, a count and `argparse.REMAINDER` (`"..."`) take the values CPython gives them, at the top level and inside every subcommand, and the usage line and the error text (`expected at least one argument`, `expected 2 arguments`, `the following arguments are required: ...`) are CPython's. The namespace has no absent slot, the same family as divergences 43 and 94: a list-valued option that does not appear (`nargs="*"`, `"+"`, a count or REMAINDER on an option) reads `[]`, where CPython reads `None`. A `nargs="?"` argument needs a `default=` (and an option also needs a `const=`), because the absent value would be `None`; without them the compile stops with `PS2003`. A list-valued `nargs` takes no `default=`, `type=Path` takes no `nargs`, and `nargs` only combines with the `store` action. `nargs="A..."` (PARSER) and `argparse.SUPPRESS` stop the compile with `PS2003`. A numeric `const=` is read by `nargs="?"` only (`store_const` keeps the str `const`). `probes/differential/argparse_nargs.py` and `probes/differential/argparse_nargs_subparsers.py` compare the parsed values and the error paths byte for byte, and `probes/divergences/d95_argparse_nargs_absent.py` shows the absent-option difference.

96. The `sqlite3` subset (issue [#1343](https://github.com/sigilco/pyscriptc/issues/1343)) is the connection/cursor shape over the vendored SQLite amalgamation the `pyscriptc-sqlite` adapter carries: `sqlite3.connect(path)`, `db.execute(sql, params)`, `db.executemany(sql, rows)`, `db.commit()`, `db.close()`, `cur.fetchone()`, `cur.fetchall()`, `cur.rowcount`, `cur.lastrowid` and `cur.description`. A `?` parameter is bound from a tagged dynamic value, so an `int`, a `float`, a `str` and a `None` each bind their own SQLite storage class, and a NULL column reads back the None arm (`value is None` is the runtime's tag test, `isinstance(value, int)` narrows the cell). The count rules are CPython's own: `rowcount` is `-1` for a statement that is not an `INSERT`, `UPDATE`, `DELETE` or `REPLACE` (the first token after whitespace and comments decides, so a writing `WITH` reports `-1` the way CPython's DML sniffing does), the changed rows for a DML run, and the sum of the runs for an `executemany` over a non-empty sequence (`0` for an empty one); `executemany` refuses a non-DML statement with `RuntimeError` where CPython raises `ProgrammingError`; `lastrowid` is the rowid of the last insert after a `db.execute`, `0` when no insert ever ran, and the subset answers `0` where CPython answers `None` on a cursor no `execute` ran on. The seams are these. The row is a `list[object]` in column order, where CPython's cursor row is a tuple, so a program that prints the row or indexes it by a name behaves differently: the name is `cur.description`'s element. `cur.description` is the list of the column names, where CPython's is a tuple of 7-tuples (the name, the type code and the five metadata slots), so the element and the type differ; the None-or-names shape, the count and the presence compare. `connect` takes the path only: `timeout`, `isolation_level`, `detect_types`, `factory`, `check_same_thread` and `uri` are refused (`PS2003`), so the busy timeout is SQLite's default and the transaction handling is the connection's own. There is no `row_factory`, no `text_factory`, no `create_function`, no `blobopen`, no `backup`, no `serialize`/`deserialize`, no `set_authorizer`, no `set_progress_handler`, no `load_extension`, no `enable_load_extension` and no `Row`/`RowIterator` class: the module's other names fence with `PS2001`. The exception class is `RuntimeError` where CPython raises `OperationalError`, `ProgrammingError`, `IntegrityError` or `DatabaseError`: the message is SQLite's own text with the `sqlite3: ` prefix, so a program that catches the specific class behaves differently. `db.close()` consumes the handle, so a statement on the closed connection is the compile fence `PS4010` where CPython raises `ProgrammingError` at run time. The `while row is not None:` narrowing is not lowered (the `if` and `assert` forms are), so a row loop spells `while True:` with an `if row is None: break`. The differential probe `probes/differential/sqlite3_params.py` byte-compares the surface with the pinned CPython (stdout, stderr and the exit code): a `?` parameter bound to an `int`, a `float`, a `str` and a `None`, the NULL round trip, `cur.rowcount`, `cur.lastrowid` and the description's presence and count. Issue [#1343](https://github.com/sigilco/pyscriptc/issues/1343).
97. A fixed-shape tuple default and a fixed-shape tuple class attribute (issue [#444](https://github.com/sigilco/pyscriptc/issues/444)) materialize a fresh record per read, where CPython holds one tuple object. A class attribute (`pair: tuple[int, int] = (1, 2)`) is one object in CPython's class dictionary, so `C.pair is C.pair` is True there and False in the lowered program; the same holds for the tuple default of a dataclass field (`a: tuple[int, int] = (1, 2)`), where CPython shares one tuple between the class attribute and every instance that takes the default and the lowered program gives each a fresh record. The values are element for element equal, so only an identity comparison tells the two apart. Source: `src/pyscriptc/lower/_classes.py` (the class-constant and tuple-default paths).
98. The compare and ordering operators resolve their dunder from the operand classes' static mro with a fixed order (issue [#445](https://github.com/sigilco/pyscriptc/issues/445)): for `a == b` (and `!=` through `__ne__`, or as the negation when no user `__ne__` resolves), the left class's `__eq__` definer is called when its parameter accepts the right class, then the right class's `__eq__` with the operands swapped, then the identity fallback (a pointer compare when the two classes share one inheritance chain, the constant `False` when no lowered class inherits from both). For `<`, `<=`, `>`, `>=` the order is the left definer of the operator's own dunder, then the right class's reflected dunder with swapped operands (`__gt__` answers `<` and so on), and the fence `PS2004` when neither resolves, where CPython raises `TypeError` at run time. CPython's reflected retry happens when the direct dunder returns `NotImplemented`; the lowered order never tries the other operand, a `return NotImplemented` fences at its return with `PS2002`, and a class pair whose comparison relies on that run-time fall-through does not compile. An `__eq__` parameter annotated `object` and narrowed with `isinstance` keeps the `PS2001` fence. Issue [#445](https://github.com/sigilco/pyscriptc/issues/445).
99. `hash(x)` on a class resolves `__hash__` statically (issue [#445](https://github.com/sigilco/pyscriptc/issues/445)): a definer's `int` result passes through with `-1` mapped to `-2` (CPython reserves `-1`), a class that defines `__eq__` without `__hash__` fences `hash()` at the call with `PS2004` where CPython raises `TypeError` at run time, and with neither dunder defined the value hashes by address, so the numeric hash is address-dependent in both implementations and no byte comparison is promised. `dict` and `set` keys stay `int` or `str`: a class key is refused with `PS2002` where CPython hashes the key through `__hash__`. Truthiness of a class-typed value follows the same static resolution: the `__bool__` definer, else the `__len__` definer compared against zero (with `__len__`'s negative-result `ValueError`), else the constant `True`; an `Optional[C]` tests its tag first and then the payload when `C` defines one of the two, and a user `__format__` definer is called with the f-string or `format()` spec where it was previously ignored. The resolved surfaces are byte-identical in the differential probe `probes/differential/protocol_dispatch.py`; the address-dependent hash and the unhashable and class-key fences are the rest of the entry. Issue [#445](https://github.com/sigilco/pyscriptc/issues/445).
100. An exception raised inside an `asyncio.to_thread` worker does not reach the awaiter (issue [#400](https://github.com/sigilco/pyscriptc/issues/400)): the worker record (`PsThreadCall` in `src/pyscriptc/runtime/ps_async.c`) carries the result value and a done flag and no exception slot, so the worker's raise ends the process where the worker ran. CPython hands the exception to the awaiting task, so an `except ValueError` around `await asyncio.to_thread(boom, 1)` runs its handler and the program continues; the lowered program prints the exception on stderr and exits 1, and neither the handler nor the statements after the `try` run. The seam is the same for the direct await and for a task wrapping the call (`create_task`/`gather`/`wait_for` over a `to_thread` frame all surface the value path only). The probe is `probes/divergences/d100_to_thread_worker_exception.py`. Issue [#400](https://github.com/sigilco/pyscriptc/issues/400).
101. The enum subset (issue [#451](https://github.com/sigilco/pyscriptc/issues/451)) answers the member surface CPython spells on every member: `.value` is the value the enum body spelled, `.name` is the name the body spelled it under, and an enum class body may spell methods and properties, which every member answers with the member bound as `self`. The `StrEnum` and flag bases join the base set: a `StrEnum` member is a str (its annotation erases to `str`, and `auto()` spells the member's name in lower case as the value, the way CPython does), an `IntFlag` member is an int (its annotation erases to `int`, so the bit operators run as the integer operators), and a `Flag` member is an int value under the enum class's own annotation. The seams are these. The lowered member is the value itself, not a member object: `print(Color.RED)` prints the value `1` where CPython prints `Color.RED`, `Color.RED is Color.RED` compares two values where CPython compares one member object, and a method's `self` is the value, so `self.value` and `self.name` are not readable inside an enum method (`self` is the int or str the member carries). The flag combination is the integer sum, so `Perm.READ | Perm.WRITE` is the int `3` where CPython answers the `Perm.READ | Perm.WRITE` member, and a flag member's `.name` for a combination has no answer (the combination is not a member of the enum). A plain `Enum` member is not an int at the type level, so a slot or a parameter the annotation names keeps the enum class type, the divergence the integer subset already carries. The member surface is byte-identical in the differential probe `probes/differential/enum_members.py` (the value and name reads of every base, the enum methods and properties, the StrEnum method, and the flag arithmetic). Issue [#451](https://github.com/sigilco/pyscriptc/issues/451).
102. A `functools.cached_property` getter (issue [#440](https://github.com/sigilco/pyscriptc/issues/440)) lowers to one accessor method per cached property: the first read calls the getter once and stores the value in the instance's hidden slot, every later read answers the stored value, and each instance owns its slot (the compiled surface is byte-identical to CPython's in `probes/differential/cached_property.py`). The seams are the class dictionary's. CPython writes the cached value into the instance `__dict__`, so `vars(obj)` shows it and the value shadows the descriptor; the lowered program keeps it in the struct slot and has no instance dictionary, so `vars` is not a lowered call at all. A write to the cached name (`c.y = 5`) is a compile fence (`PS2001`) where CPython stores the value into the instance `__dict__` and the name then answers the stored value without ever running the getter. The class-level read `C.y` returns the descriptor object in CPython and fences in the lowered program, the same rule every method name follows. The getter's return type must be a storable struct-field type (`str`, `int`, `list`, `dict` or a pointer class; a `float`, a `bool` and a tuple keep the `PS2002` fence), and `__set_name__` is never called (the descriptor protocol is refused by design, the PS42xx family). Source: `src/pyscriptc/lower/_classes.py` (the accessor synthesis and the hidden slots), `src/pyscriptc/lower/_classes_more.py` (the decorator kind).

103. A `unicodedata` argument that is not a one-character string raises `ValueError` where CPython raises `TypeError` naming the length (`category(): argument must be a unicode character, not a string of length 2`): the ABI carries the buffer length, so the one-character check is the runtime's own raise. The value paths (the category, the name, the lookup, the combining class, the numeric values, the decomposition, the four normalization forms) answer over the whole code-point range from the generated Unicode 16.0.0 tables (issue [#476](https://github.com/sigilco/pyscriptc/issues/476)), and the probe `probes/divergences/d103_unicodedata_codepoints.py` byte-compares the range the old Latin-1 table could not answer.
