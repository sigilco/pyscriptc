# Stage-2 fixed-point lane

The Stage-2 fixed-point lane (issue #831, roadmap R6) lowers every importable
module under `src/pyscriptc` to canonical IR, hashes each module, and compares
the hash maps across two runs. The first state is self-vs-self: the seed
interpreter compiles the tree twice, so any per-module divergence is a real
nondeterminism leak, not a migration artifact. When the self-compiled binary
can compile the tree, the same `compare_runs` driver reports seed-vs-self, and
the per-module divergence count becomes the headline self-host receipt,
trending to zero as the typed-IR migration lands.

## Running it

```
uv run python -m benchmarks.compat2.fixpoint [--src DIR] [--out FILE] [--summary FILE]
```

Exit 0 when the fixed point held, 1 when any module diverged. `--out` writes
the full JSON report (run digests plus the per-module report); `--summary`
writes a markdown table with one row per module (match or DIVERGENT), which is
what the CI job summary shows. The lane lowers every module twice, so it
takes a few seconds on the current tree.

## CI

The `fixpoint` job in `.github/workflows/ci.yml` runs the lane on every
compiler-path change and on master pushes. It is NOT a required check: the
headline is the per-module divergence table in the job summary, and a new
divergence is a signal for the migration, not a merge blocker.

## Gate files

`benchmarks/compat2/fixpoint.json` is a receipt snapshot, not a frozen gate
file: it is regenerated by hand at slice boundaries. It is unrelated to
`probes/TIR_HASHES.json` (the streaming-serializer golden gate, decision
2026-11-03), which keeps its own regeneration ritual and is untouched by this
lane. The full spec section is `.agents/docs/spec/ir-canonicity.md` section 7.5.
