# Parallel PR merge rules (refs #817, v0.9.0 flip plan stage D)

Several sessions land MIR and lower/ work at once. The merge hotspots are
known and mostly mechanical; the rules below keep parallel PRs from
deoptimizing each other. `scripts/rebase_helper.py` automates the
rebase-onto-master flow for the generated files.

## Declare owned files

Every parallel PR body lists the files it owns. Two open PRs must not edit
the same file except for the generated artifacts below, which are
regenerated, never hand-merged. At most one open PR may append MIR ops
(`src/pyscriptc/mir*.py` op tables and `mir.py` constants): op ids are
baked into serialized digests, so ids are never renumbered: a new op
family takes a fresh id block above the highest existing id, and the owner
is recorded in a `mir.py` comment next to the constants.

## Generated artifacts: regenerate, never hand-merge

- `tests/census_pins/<module>.json`: per-module fence ceilings, one shard
  per module. Only `uv run python scripts/repin_census.py` writes them; a
  repin touches only the shards whose measured count moved, so `git status`
  after a repin shows exactly your modules. Details: `census-pins.md`.
- `data/compat/support.json`: generated by
  `uv run python scripts/gen_support_table.py` from compiler probes and
  `scripts/support_data.toml`; `--check` mode is wired into
  `scripts/pre_push_hook.py` (`mise run check:fast`) and
  `tests/test_support_docs.py`. Never hand-edit or hand-merge it.
- `tests/fixtures/mir_leaf/` and `tests/fixtures/mir_print/`: fixture
  discovery replaced the hand-maintained sample lists; adding a fixture or
  a `.mir` golden needs no test-list edit.

## Rebasing onto master

```
uv run python scripts/rebase_helper.py
```

It runs `git fetch` + `git rebase origin/master` and resolves the three
mechanical conflict shapes:

- `data/compat/support.json`: takes the onto side, then regenerates with
  `gen_support_table.py` after the rebase. The manual equivalent on a
  conflict is `git checkout --ours data/compat/support.json && uv run python scripts/gen_support_table.py`.
- `tests/census_pins/` shards (and the retired `tests/census_pins.json`):
  takes either side mid-rebase, then `repin_census.py` rewrites every shard
  from the merged tree.
- anything else: the helper stops with the conflicted file list and leaves
  the rebase in progress. Resolve by hand, `git rebase --continue`, or
  `git rebase --abort`.

After a clean rebase the helper regenerates both artifacts; if that leaves
the tree dirty it prints the changed paths and stops without committing, so
the regeneration commit stays deliberate. Frozen gate files
(`benchmarks/compat2` hashes, probes, `outcomes.py`) are never
auto-resolved: a conflict there stops the helper.
