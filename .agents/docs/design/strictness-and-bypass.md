# Strictness levels (issue #1315) and a user bypass: KISS review before the levels ship

Status: design note, 2026-11-19, session rsH. Research note, not a decision. The decision rows proposed at the end are what turn it into one.

Inputs: `.agents/docs/design/typing-quality-lane.md` (rsC, the levels design this note reviews), `.agents/docs/design/loose-typing-and-default-inference.md` (#1283, default-on pins), `.agents/docs/design/island-promotion-and-annotation-surface.md` (rsB, the shadow module and `@island`), `.agents/docs/design/library-blocks-and-class-bases.md` (rsE, the end state where only language fences block), `.agents/docs/design/tagged-dynamic-value.md` (#1226, the `object`/`dyn` design and its rejected alternatives), the branch `work/imp1315` (read, not extended: `src/pyscriptc/typinglevels.py` 495 lines, `src/pyscriptc/infercoverage.py`, the `typing_policy()` wiring in `src/pyscriptc/config.py`, the `assess.py` `_typing_section` hook, `docs/guide/python-subset.md` levels section, 31 passing tests in `tests/test_typing_levels.py`), and the peer sources cited inline. Owner direction 2026-11-17 frames both questions: typing is a QUALITY lane, never an ADMISSION lane, and a codebase fails to lower only for language-wise walls.

## Question

Two sub-questions. (1) The rsC recommendation and the `work/imp1315` implementation ship four report-only strictness levels (`off`/`basic`/`standard`/`strict`), per-level glob lists in `[tool.pyscriptc.typing]`, and a raise-only `# pyscriptc: typed=` pragma. With typing demoted to a quality lane and inference default-on, are four levels, globs and a pragma useful, or is this a strictness apparatus copied from checkers whose strictness gates errors, when here nothing gates? Who would set each level, what actually changes, and what is the minimal alternative? (2) Should there be a user bypass for the owner who is certain how their codebase works: what would it bypass, what do the precedents (Rust unsafe, TypeScript `as`/`any`/`@ts-ignore`/`@ts-expect-error`, mypy `cast` and `type: ignore`, Sorbet `T.unsafe`, Cython directives, C# unsafe) teach, what could it break, what stays un-bypassable, and is island demotion already the safe bypass?

## Evidence

### What strictness buys in the checker world, and why the argument does not transfer

Strictness levels exist in checkers because strictness changes which *errors* the tool raises, and errors gate: CI fails, the editor goes red, the build stops. Pyright's four modes (`off`/`basic`/`standard`/`strict`, `typeCheckingMode`, default `standard` at a config file, `off` by default in the VS Code settings surface) are a table of per-rule severities, roughly a hundred rules, most of which error in every mode above `off` (https://github.com/microsoft/pyright/blob/main/docs/configuration.md, and PR 8704 documenting the defaults). Sorbet's five `# typed:` sigils change which errors a file raises, and Stripe's adoption story is a ratchet over an error gate (https://sorbet.org/docs/static, https://shopify.engineering/adopting-sorbet). Mypy has no named levels, just flag bundles; `--strict` composes `--disallow-untyped-defs` and friends (https://mypy.readthedocs.io/en/stable/command_line.html). Ty ships no presets at all, only per-rule severities (https://docs.astral.sh/ty/coming-from-mypy-or-pyright/). In all of them, at every level above `off`, type errors are errors.

In pyscriptc after the 2026-11-17 direction, no report severity gates anything. `compile` succeeds or fences on language grounds regardless of level. `assess` and `pyscriptc infer --report` are diagnostics. So a level can only change which lines appear in a report nobody gates on. That is the whole KISS question in one sentence: the levels cost real surface (a 495-line module, a config table, a pragma parser, a glob matcher written by hand, a severity algebra, docs) to vary output that controls nothing.

Who would set the levels, concretely? The adoption-ratchet user exists in principle (raise globs file by file as annotations land), and rsC cited the Pyright gradual-adoption guide as the story (https://github.com/microsoft/pylance-release/blob/main/docs/howto/gradual-strict-adoption.md). But the ratchet story needs the gate to mean something: Pyright's phase 5 is "strict across the project" because strict errors block merge. pyscriptc's equivalent ratchet has no enforcement hook anywhere: nothing in CI runs `assess --fail-on-error` today, the levels do not touch exit codes by design, and `docs/reference/config.md` documents no gating key. A ratchet over an unenforced report is a preference, and a preference needs at most one knob.

What the level ladder would actually show. The missing-annotation findings the lower levels report (PS1001 family) are exactly what the default-on pin engine already answers better per construct, and the coverage report (`pyscriptc infer --report`, #1304, shipped as `infercoverage.py`) already counts unannotated parameters, pins, and pin rate per module. The construct-form findings the strict level adds (PS1103/1104/1105/1106) are already the compiler's own fences: a file that uses a quoted forward reference or a `Callable` bare gets the PSxxxx fence from the lowerer itself when it matters. `typinglevels.py`'s static scan re-derives, from the AST with its own name lists (`GENERIC_ALIAS_NAMES`, `DYNAMIC_NAMES`), findings the compiler already emits with checked semantics; the two lists can and will drift from the lowerer's real tables (`lower/_annotations.py`, the construct table in `docs/guide/python-subset.md`). The four-level scan is a second, weaker implementation of information the toolchain already reports.

The empirical backdrop says the untyped mass is not a ratchet audience. The Meta/Microsoft/JetBrains typing survey (2024, 1,083 respondents) found 88% always or often use types, and the driver list is IDE support, docs, and bug-catching, all checker-side benefits (https://engineering.fb.com/2024/12/09/developer-tools/typed-python-2024-survey-meta/). The empirical annotation studies find the opposite of a strictness ladder in the wild: under 10% of possible elements annotated even in annotation-using projects, 78.3% of commits integrated despite detectable type errors, three adoption patterns of which two are not progressive at all (Di Grazia and Pradel, ESEM/FSE 2022, https://dl.acm.org/doi/pdf/10.1145/3540250.3549114; and "Python 3 Types in the Wild", DLS 2020: only 101 of 2,678 typed repos even carry a mypy config, https://hirzels.com/martin/papers/dls20-python-types.pdf). Developers who ignore checker errors will not tune four report levels on a compiler report. The realistic pyscriptc user wants one answer: what will fence, and what will the pins lift. That is one report, not four levels of it.

### What the implementation already costs (read from `work/imp1315`, not extended)

`typinglevels.py` carries: a hand-written glob matcher (`_glob_here`, recursive `*`/`**`/`?` with path-segment rules, a documented divergence from `fnmatch`), the `TypingPolicy` resolution with a three-key tie-break (longest pattern, strictest level, config order), the pragma parser with an error on unknown levels, the severity algebra (`severity_for`, `reports_coverage`), the `Finding` dataclass, and the AST scanner with its own copies of which generic aliases and dynamic names fence. `config.py` grows a validated `[tool.pyscriptc.typing]` table; `assess.py` grows `_typing_section`; `cli/_report.py` grows `_typing_policy`; the guide grows a levels section. Every one of these is correct as written (31 tests pass, run on this host: `uv run pytest tests/test_typing_levels.py -q`, "31 passed in 7.51s"). The cost is not bugs, it is surface: five integration points and a second semantic copy of the fence taxonomy that must track the lowerer forever, for a dial with no consumer.

### The bypass precedents, and what each one's guard is

Rust `unsafe`: a syntactic block that unlocks a short, documented list of extra powers (raw pointer dereference, calling `unsafe fn`s, mutable statics). It cannot disable the borrow checker, and the ecosystem norm (clippy `undocumented_unsafe_blocks`, the `# Safety:` comment convention) demands a justification at each block (https://doc.rust-lang.org/book/ch19-01-unsafe-rust.html). The lesson: a bypass is acceptable when the powers it unlocks are enumerable, each carries an invariant someone must uphold, and the bypass is visible in review.

TypeScript: the ladder is `as T` (a checked-where-possible assertion that still compiles to nothing), `as unknown as T` (the launderer), `any` (a value-level hole), `@ts-ignore` (line-level suppression that goes stale silently), and `@ts-expect-error` (suppression that errors when unnecessary, so stale suppressions surface). The field data is instructive: WordPress Gutenberg's migration found 35 of 117 `@ts-ignore` comments (30%) were stale, suppressing nothing, and converted the rest to described `@ts-expect-error` (https://github.com/WordPress/gutenberg/pull/81148); a five-codebase census found suppressions near zero (one `@ts-expect-error` in 31k lines) where `strict` errors actually gate, and type assertions doing the real bypassing instead (https://nowaterprogramming.com/blog/typescript-suppression-comments-measured); and the Microsoft internal report (TypeScript issue 47551) shows line-level suppression is overly broad, suppressing *new unrelated* errors on the same line (https://github.com/microsoft/TypeScript/issues/47551). The ecosystem's converged answer is `@ts-expect-error` plus `no-explicit-any` linting: bypass locally, described, and self-expiring. The lesson: suppression beats casting for auditability, expect-style (must be used or error) beats ignore-style (rots), and any silent bypass surface gets laundered (`as unknown as T` exists to route around lint).

Mypy: `cast(T, x)` (an assertion, no runtime effect, checker-trusted), `reveal_type` (a query, not a bypass), and `# type: ignore[code]` with error codes, where the code-specific form is recommended over bare ignore precisely because bare ignore hides unrelated future errors (https://mypy.readthedocs.io/en/stable/syntax_notes.html). Sorbet: `T.unsafe(x)` and `T.must`, with the same shape: a value-level assertion, not a file-level off switch. Cython: directives (`boundscheck`, `wraparound`, `infer_types`) compile-time knobs with defined semantics per scope; turning off bounds checking removes a *runtime check* the generated code would have inserted, and the docs say what you forfeit (https://docs.cython.org/en/latest/src/userguide/language_basics.html). C# `unsafe`: again an enumerable power list (pointers), scoped to a block or type, nothing else changes.

The common shape across all of them: the bypass (a) unlocks an enumerable power or suppresses an enumerable diagnostic, (b) is per-definition or per-value, never per-project, (c) is visible in the source at the exact site, and (d) the best ones (Rust unsafe with the safety comment, `@ts-expect-error`, `type: ignore[code]`) require or reward a stated reason and expire when the reason disappears. None of them is a debug flag that turns the checker off.

### What a pyscriptc bypass could target, and the adversarial pass

Three candidate targets, by what they guard. The adversarial pass below runs against each.

Candidate 1: a PSxxxx fence on a construct the owner knows never executes or never matters. This is what island demotion already is. rsB's `@island` decorator routes the marked definition to embedded CPython on purpose and the compile and assess name the routing (divergence 41, the `demoted by marked @island` plane-map entry; the marker routing is merged, `feat(island): route the @island marker definitions to the island lane (#1322)`). rsE generalizes it: every library-shaped refusal becomes island routing; only language fences inside definitions with no island route block. The bypass a PS2002/PS1203-fenced class or a PS2006 decorator needs already exists, is per-definition, keeps CPython semantics (the island *is* CPython), and is reported, not silent. Adding a separate fence-suppression mechanism next to it would be a second, worse spelling of demotion: one that removes the definition from the binary instead of running it correctly.

Candidate 2: an inferred-type conflict, i.e. overriding a pin or an annotation. Any spelling of this is a self-inflicted miscompile. The pin rule (tree-wide agreement, never overrides annotations) and the annotation-is-the-input rule exist so the emitted native code matches what the checker proved. A `# pyscriptc: assume(x: int)` style bypass would let the user assert a type the call sites contradict, and the emitted code trusts it: wrong arithmetic, wrong narrowing, memory-unsafe reads through a wrongly typed container (an `int` read of a slot holding a `str` is an unchecked load in the IR). The failure would be indistinguishable from a compiler bug in the user's report, which is the worst outcome a small project can buy: every bypass-enabled miscompile is a misattribution risk against a binary whose selling point is sound lowering. Rust refuses to let `unsafe` touch the borrow checker for exactly this reason; TS makes `any` loud (`no-explicit-any`); none of them lets you override a proven type in place.

Candidate 3: a native-lowering precondition, like an unchecked cast at a boundary. The compiler's own analogues are the PS1107 read fence (an unresolved `dict[K, Any]` read must be proven or it fences, and the tagged-dynamic-value note explicitly rejected dropping that fence as "removing a fence that has earned its place": `.agents/docs/design/tagged-dynamic-value.md` alternative A) and the growth-shape island routing for unbounded ints. A bypass here would be `cast`-shaped: "I assert this read yields int". The harm is the same as candidate 2 but narrower, and the safe spelling already exists: write the narrowing the language supports (`isinstance`, which compiles to the runtime's tag compare and narrows the branch, per the construct table) or route the function to the island. The honest version of a cast, if one is ever wanted, is a runtime-checked cast (narrow or demote), never a compile-time-only assertion.

Adversarial summary: any bypass that changes what the lowerer trusts converts soundness into an unverified user claim. The failure modes are memory-unsafe native reads, wrong arithmetic, ABI breakage at island crossings (a native signature that does not match what the island caller passes), miscompiles that blame the compiler, and a support surface of "your assertion was wrong" bug reports that are unfalsifiable from the binary. None of these failure modes exists for island demotion, which is why demotion is the bypass to keep.

What must stay un-bypassable regardless of any future mechanism: the parity contract (emitted semantics fixed at ship time, `docs/reference/divergences.md`), the annotation-is-the-lowering-input rule, the pin agreement rule, the native ABI at island crossings, and the differential-probe escape hatch discipline (any accepted divergence gets a ledger entry in the same PR, never a user-side silence).

## Options

### Option L: the strictness apparatus (what `work/imp1315` implements)

Four levels, globs, raise-only pragma, severity algebra, static scan. As built it is report-only, correct, tested, and inert for projects that configure nothing. Its costs: the second fence taxonomy that will drift from the lowerer's, five integration points, docs, and a knob with no gating consumer.

### Option L1: shrink to one boolean (`--typing-report` / `[tool.pyscriptc.typing] mode` only, two values on/off)

Keep the scan and the report, drop the level ladder: either the typing findings surface or they do not. Keeps the useful artifact (the report says what fences and what the pins lift), deletes the severity algebra, the raise-only rule, the tie-break, and the four-way PEP mapping. Cost of the change on `work/imp1315`: mostly deletion; `severity_for` collapses, the pragma and globs go.

### Option L2: keep the levels but gate them on a consumer (Sorbet story only after `--fail-on` exists)

Ship levels only together with a CI-consumable gate: `pyscriptc assess --typing-fail-on error` (or a config key) so a level can hold a ratchet in CI. This restores the thing that makes strictness useful in every peer. Cost: a new admission-adjacent surface, which is in tension with the quality-lane direction (it does not gate `compile`, but it gates CI), plus all of L's costs plus a flag.

### Option L3: drop levels entirely; the coverage report is the typing report

`pyscriptc infer --report` (#1304, already shipped on master per `work/imp1315`'s base) already answers the quality question with checker-proved numbers: unannotated surface, pins applied, pin rate. The compiler's own fences answer the construct-form question with ground truth. Delete `typinglevels.py` and its five integration points; the typing report is one artifact with one default.

### Option B: the bypass designs

B1. Island demotion as the bypass (status quo, sharpened): keep `@island` as the only escape, and make its story explicit in docs: "certain how the codebase works and the compiler disagrees on one definition? route that definition to the island; the binary runs it under CPython and the plane map records the choice." Zero new mechanism; the escape is semantically safe by construction (island runs real CPython).

B2. A debug/report-only escape hatch: not a bypass of lowering at all, but an `assess`/`compile --debug` presentation switch that explains *why* a fence fired and what the safe route is (which decorator, which lane). This answers the underlying want (the owner who is certain is usually certain because they know the fence is on a path that never runs) without any soundness surface.

B3. A true cast/assert bypass (`pyscriptc._annotations.cast(T, x)` or a `# pyscriptc: assume` pragma) that overrides an inferred conflict or a PS1107 read: rejected per the adversarial pass. If a cast is ever justified by evidence (a measured population of PS1107 fences in JSON-heavy trees that the tagged-dynamic value and isinstance narrowing genuinely cannot express), it must be a runtime-checked narrowing, shipped with its own divergence ledger entry, never a compile-time-only trust-me.

B4. An `unsafe` block (`with pyscriptc.unsafe():`) scoping a small enumerated power list: rejected for now as unfundable. pyscriptc has no enumerable "extra powers" list yet whose soundness a user could meaningfully uphold; the only candidate powers (raw ABI, unchecked reads) are exactly the miscompile generators above. Revisit only if a native-ABI extension surface ever exists for users.

## Recommendation

Strictness levels (#1315): shrink, do not ship the ladder. Reject L as designed and L2 (levels are machinery for a ratchet with no gate, and the empirical evidence says the audience that tunes four report levels does not exist for a compiler whose real quality answer is one report). Recommend L1 or L3, with L1 as the do-now shape and L3 as the target if the pruning stays cheap: one typing report, optionally quietable (`mode = "off"` covers silence), no glob lists, no pragma, no severity algebra. Concretely: keep the AST scan and the report wiring from `work/imp1315`, delete `TypingPolicy`'s glob resolution, the pragma parser, the raise-only rule and the severity ladder, and reduce `[tool.pyscriptc.typing]` to `mode = "standard" | "off"` (default `standard`, so the report is on and one key silences it). The second fence taxonomy (the scanner's own name lists) should read the lowerer's tables rather than duplicating them, whether L1 or L3 ships, so the report cannot drift from what the compiler actually fences.

Bypass: adopt B1 and B2, reject B3 and B4. Island demotion is the safe bypass and it already exists (`@island`, merged #1322); the docs change is one paragraph in `docs/guide/python-subset.md` naming it as the escape for the certain owner. The certain owner's real need is explanation, not suppression, and B2 (the debug view that names the fence, its reason and its safe route) serves it without touching what the lowerer trusts. A compile-time cast that overrides a proven type stays rejected with the tagged-dynamic note's Alternative A reasoning recorded against it; a runtime-checked cast is the only future shape, and it is gated on evidence that does not exist yet.

First PR-sized steps: (1) on `work/imp1315`, the shrink to one config key and the deletion of the ladder surface, with the guide section reduced to the one-report paragraph (or, if the owner prefers the full ladder, L2's `--typing-fail-on` consumer must land in the same PR as the levels); (2) the docs paragraph naming `@island` as the certain-owner escape; (3) the scanner's name lists read from the lowerer's tables (one source of truth for the fence taxonomy).
