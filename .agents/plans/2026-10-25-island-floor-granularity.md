# Island floor granularity: what falls to CPython, and how

Date: 2026-10-25. Status: design plan for issue #597, milestone v0.7.0.
Grounding: `.agents/plans/2026-10-25-typed-subset-positioning.md` (Decisions 2, 3, 5, 7), issue #597, the dogfood evidence in `<session-notes>/dogfoodapp.out.md` (8 real scripts, 0 ran) and `<session-notes>/dogfoodisland.out.md` section "Failure clusters" (C1 to C6).

Problem today: island routing covers only imports (`[tool.pyscriptc.imports]` plus `--island`, `src/pyscriptc/cli.py:236` and `cli.py:330`). The first unlowered construct inside the user's own script raises `Fence` (`src/pyscriptc/lower/__init__.py:851`), `compile` prints the fences and returns 3 (`src/pyscriptc/cli.py:1509`), so no binary exists at all. Even on the island route, an unannotated island call result hits `PS1001` at `src/pyscriptc/lower/_stdlib.py:846`, because `_island_call` (`_stdlib.py:804`) returns an opaque handle and only `_island_getattr` (`_stdlib.py:834`) unboxes. Result: 0 of 8 dogfood scripts ran, and the "floor" is not a floor for the user's own code.

## Decision A: the fallback unit is the definition; module top level is all-or-nothing

Per-definition. A function (or class body) lowers native iff its body produces zero fences; otherwise, under the fallback tier, the whole definition runs in the island. This is the same split `pyscriptc coverage` already computes as a report: `capabilities()` in `src/pyscriptc/coverage.py:290` marks each definition native, fenced or island from the fences inside it, and `Fence` already records the enclosing function (`src/pyscriptc/lower/_core.py:16`, set by `fail()` at `src/pyscriptc/lower/__init__.py:851`). The design turns that existing classification into enforcement: the router and the reporter read one structure, so what `assess` predicts is what the binary does (this also fixes dogfood finding A5, where assess recommended a route the island could not take).

Module top level executes in exactly one plane. If any module-level statement fences, the whole top level runs island-side (as the `__main__` body of the embedded interpreter); if none fences, it lowers native as today. Half-native top level is refused by construction: `PS1001` for unannotated module locals stays the fence when the fallback tier is off (`src/pyscriptc/lower/_stmt.py:830`), and with the tier on the module body simply executes under CPython. Three of the eight dogfood scripts (`check-deploy-secrets.py`, `validate.py`, `classify.py`) die exactly there, on `ROOT = Path(__file__).resolve().parent`.

Rejected granularity, per statement: a fenced statement would bail mid-function and resume its neighbors native, which needs a dynamic value type for the locals that live across the bail. The IR deliberately has none: `Any` is refused (`PS1104`, `src/pyscriptc/diagnostics.py`), unions are refused (`PS1101`), and the guarded-speculation/deopt architecture that could carry dynamic locals was permanently dropped by the positioning plan (Decision 1). It would also violate the compat-effort rule: the compiler never grows a special-case shim for untyped code. Per-module-only is not adopted either, but it falls out of this design as the degenerate case where every definition fences (`tool_token_analysis.py`: 0 of 17 native), so nothing is lost; `binary_size.py` keeps its 3 of 13 native functions that whole-module would throw away.

## Decision B: typed functions stay native, untyped ones run on CPython

A definition with zero fences lowers to LLVM as today. A definition with any fence becomes an island function: the compiler embeds the module's source text in the binary, the embedded interpreter execs it once at island init (with `__name__` set so `if __name__ == "__main__":` does not fire inside the island; the entry shim invokes the registered entry itself), and every call site that targets an island function lowers to a new trampoline `ps_island_fn_invoke(mod, name, args)` beside `ps_island_call` (`src/pyscriptc/runtime/ps_island.c:554`). The island function keeps CPython semantics for free: closures, generators, kwargs, dynamic attributes, exceptions.

Native calling island, seam 1 (positioning Decision 3), rules at the call site:

- Arguments: scalars, `str`, `bytes` and lists of scalars cross by value (the existing `PsArg` marshalling, `ps_island_from_arg` at `ps_island.c:380`). A `dict` or any other object crosses as an opaque handle. A native list is copied, so island-side mutation is not visible to the native side; that is a documented divergence, consistent with value-only marshalling.
- Return: with an annotated scalar/str/bytes/list return, the trampoline unboxes via the `want` mechanism `ps_island_set_arg` already has (`ps_island.c:458`), exactly as `_island_getattr` does today; this generalizes #602 from attribute reads to call results. Without an annotation the result is an opaque handle, usable through `ps_island_getattr`, a new `ps_island_getitem`, `ps_island_call` on it, and `ps_island_format` for printing (`str()`/f-string of a handle), never by native operators. The dogfood canonical `cfg = yaml.safe_load(MANIFEST.read_text())` then runs: `cfg` is a handle, `cfg["deploy"]` unboxes through `getitem`, and #597's headline fence disappears.
- Ownership: handles are owned by the enclosing native scope and released at scope exit, the discipline `_island_module_handle` already uses (`_stdlib.py:782`, `handle_locals`). No object identity survives a crossing (positioning Decision 3).

Island calling native, the inverse direction, stays out of v0.7.0. An island function whose body calls a compiled sibling fences with a diagnostic that names both functions and says the island-to-compiled seam is the `--emit binding` surface (positioning Decision 3, `#457`). This keeps "values cross a seam exactly once per direction" literally true: a compiled-to-island-to-compiled call chain would be a design bug by the positioning plan. The v0.8.0 follow-up exposes compiled functions into the embedded interpreter through the same ctypes loader the binding emits, so island-to-native reuses the seam 2 vocabulary instead of inventing a third one. Concretely for v0.7.0: when the planner moves function F to the island and F calls typed G, F's whole body runs under CPython, G is simply not visible island-side, and the fence tells the user to let G fall too (most dogfood scripts are nearly all-untyped, so this bites few call sites).

## Decision C: relation to `--fallback=cpython` and the boxed ledger

This tier is the boxed tier. The ledger (`benchmarks/compat2/boxed_cost.py`) already counts everything this design adds: `BOXED_PATHS` is `("src/pyscriptc/boxed.py", "src/pyscriptc/runtime/ps_island*")` (`boxed_cost.py:37`), so the new planner lives in `src/pyscriptc/boxed.py` (the module the ledger anticipates and AGENTS.md names) and the new trampolines in `ps_island.c` with no marker bookkeeping. Branches inside shared compiler files carry `# boxed:begin` / `# boxed:end` markers, as the existing island lowering does (`src/pyscriptc/lower/_stdlib.py` has four regions, `cli.py` seven). `NAMED_AS_BOXED` matches `island` in commit subjects, so island commits do not read as iteration tax. Every stage boundary below runs `mise run boxed:cost` and records the window in the iteration report.

Flag surface: AGENTS.md names the tier `--fallback=cpython`; the CLI spells it `--island` today (`cli.py:236`, `cli.py:330`). Stage 2 makes `--fallback=cpython` the primary spelling on `run` and `compile` with `--island` kept as an alias, so docs, ledger prose and CLI agree. Policy stays `[tool.pyscriptc.imports]` for imports and gains `[tool.pyscriptc.fallback] definitions = true` (the default when the flag is set) so a user can pin "imports only" while triaging. The framing guard from positioning Decision 2 is unchanged: the island tier does not grow while the drop flag fires, and the drop-flag thresholds stay as documented in AGENTS.md (churn 20 percent or bug 25 percent in two consecutive windows, tax 15 percent, reach falling three windows). Expectation to record now: code share rises from the 2026-10-23 window's 0.5 percent because the owner prioritized weekly usability (#597) over minimizing the tier; the ledger's job is to make that cost visible, not to veto the decision.

## Decision D: what the user sees

- `pyscriptc assess FILE` (entry `src/pyscriptc/assess.py:240`) already prints native vs island vs blocked shares; it gains the per-definition plane map (which functions would run native, which island, which stay blocked and why) and policy lines derived from the real router, so a recommendation like `fallback = "definitions"` predicts the run outcome. This retires dogfood finding A5.
- `pyscriptc run --report[=FILE.json]` prints the executed plane map after the run: per definition native or island, whether libpython was linked, and which imports crossed. Default output stays silent so `#555 verify` stderr comparisons stay byte-clean (dogfood A7 separately pollutes stderr today).
- `compile --debug-dir` already writes `summary.json`; it gains `fallback: {moduleTopLevel: native|island, functions: {name: native|island, ...}}`, which is also what the verify receipt records so a mixed-plane diff is interpretable.
- `pyscriptc imports` keeps the import ladder untouched; the definition-level split is assess/coverage/run territory, not a fifth ladder rung.

## Decision E: semantics risks, named

- Globals: island top level owns module globals. Native functions may read an island global only when its annotation is a marshalable scalar/str/bytes/list; the value is unboxed once after island init and later island-side rewrites are invisible to native code (documented divergence, one-directional like everything at this seam). Native writes to module globals are fenced in v0.7.0 with a diagnostic naming the global.
- Exceptions: today `ps_island_fail` (`ps_island.c:66`) flattens any island exception to `PS_RUNTIME` with the message only. Stage 1 maps the fetched exception type name onto the closed native exception table so `except ValueError:` in native code catches an island `ValueError`; anything outside the table stays `PS_RUNTIME` with the type name in the message. Island functions catching exceptions need nothing: they run under CPython.
- Exit codes: `raise SystemExit(main())` exits 1 and prints `SystemExit: 0` today (#603, dogfood cluster C1, universal across all eight scripts' idiom). It lands first and independently. When the module top level runs island-side, the embedded interpreter's own `SystemExit` semantics deliver the status for free; the native path needs the code fix either way.
- Closures and generators: free inside island functions (CPython executes them). Native code taking a closure or generator from the island fences with a diagnostic naming the construct; no cross-seam callables in v0.7.0.
- Threading: every island entry takes the GIL (`ps_island_ensure`, `ps_island.c:57`, the `#174` receipt), so native threads calling island functions serialize there; island functions spawning threads run under CPython's real GIL and inherit CPython semantics, adding none (positioning Decision 4).
- Determinism: island functions produce CPython's output by construction, which makes `#555 verify` diffs on mixed scripts easier to attribute; the receipt carries the plane map from Decision D.

## Staged plan

Order and scope, each with its exit receipt. Stages 0 and 1 are prerequisites that already have issues; 2 to 4 are the new work to file from this plan.

- Stage 0, S, `fix(rt): SystemExit sets the process exit status` (files as #603). Receipt: `raise SystemExit(main())` exits with main's value, stderr clean, identical for native and island binaries.
- Stage 1, M, `feat(island): unmarshal island call results into annotated locals` (generalizes #602; ships with #605 kwargs or behind it). Receipt: the dogfood tabulate case (`out: str = tabulate.tabulate(rows)`, `print(out)`) runs end to end, exit 0.
- Stage 2, M, `feat(boxed): per-definition fallback planner`. `src/pyscriptc/boxed.py` computes the plane map from the fence list (`Fence.function`, module-level split), `lower` routes fenced definitions to `ps_island_fn_invoke`, island-to-native calls fence with the named diagnostic, `--fallback=cpython` becomes the primary flag. Receipt: `maki/scripts/tool_token_analysis.py` (0 of 17 native today) runs under `--fallback=cpython` with byte-identical stdout to CPython 3.14 and the plane map in `summary.json`; `mise run boxed:cost` window recorded.
- Stage 3, M, `feat(boxed): island module top level`. When module-level statements fence, the embedded interpreter executes the module body island-side; annotated scalar globals unbox into native readers at init; the program directory joins `sys.path` in `ps_island_init` (shared with #606). Receipt: `brioso/scripts/check-deploy-secrets.py` (`ROOT = Path(...)`, `cfg = yaml.safe_load(...)`) runs to completion, exit 0; closes #597.
- Stage 4, S, `feat(cli): run --report and assess plane map`. Receipt: assess on all eight dogfood scripts prints per-definition native/island/blocked plus a policy line whose application predicts the run; `run --report` prints the executed map, default output unchanged.

v0.7.0 gets stages 0 to 3 (the floor: real scripts run weekly; stage 4 rides if the boundary allows). Deferred to v0.8.0: island-to-native sibling calls over the binding seam, the single environment contract (#606, #601, #600), `from pkg.mod import fn` island routing (dogfood C3), and binding-seam error delivery (#604).

## Recommendation

Ship per-definition granularity with island-side module top level, staged 0 to 4 above, under the `--fallback=cpython` name, with the boxed ledger measured at every boundary. This is the only granularity that (a) rescues all eight dogfood scripts without a dynamic value type in the IR, (b) keeps the native ceiling for the typed functions real scripts do have, and (c) keeps every new line inside the boxed accounting so the drop flag stays honest. The sequencing puts the two S/M seam fixes first because both are independently shippable and unblock the planner; the planner is where the design lands, and the top-level stage is what actually closes #597.

Rejected alternative: per-statement bailout with deopt (the classic JIT fallback shape). It promises finer native retention than per-definition, but it requires exactly what the positioning plan removed: a dynamic value lattice for locals live across the bail (`Any` and unions are refused by design, `PS1104`/`PS1101`) and a resumption path back into typed code, which is the guarded-speculation architecture Decision 1 permanently dropped. It would put untyped-code shims inside `lower/`, against the compat-effort rule, to save native execution of a few statements in scripts that are overwhelmingly untyped anyway. The island tier gives the same user outcome with semantics CPython already owns.
