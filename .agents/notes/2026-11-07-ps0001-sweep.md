## Findings

Zero PS0001 internal errors or crashes attributable to the MIR lane.

- `top100.tzdata` exits 1 with `PS0001: module has no functions to emit` - a
  data-only package; the same message on `PYSC_MIR=0`, so it is the existing
  direct-lane contract, not a MIR defect.
- `top100.pyasn1` crashes with an uncaught `KeyError: 'Tag'` in
  `lower/_classes.py` `_construct` (from `lower/_call_attr.py` `_call_attr`
  line ~172) - identical traceback on `PYSC_MIR=0`. A shared-lowerer bug that
  predates the MIR lane; filed as #1098 for the `lower/` owners.
- Separately found while validating the `sum(generator)` fix: the MIR lane
  crashed `PS0001: the MIR lane has no class record for gen` on any program
  whose generator frames carried `gen.*` class names (e.g. `for x in gen()` in
  an in-slice function). Root cause: `miremit._class_field_key` split the
  `<class>.<field>` key at the first dot, so `gen.g.<field>` resolved the
  class `gen` instead of `gen.g`. Fixed by splitting at the last dot
  (field names never contain dots; class names like `gen.g` and `cm.*` do).
  Regression coverage: `tests/fixtures/mir_leaf/leafgen.py`.

## sum(generator) PS2003 fence

`sum(squares(100))` in `corpus/scripts/generators_comp` fenced PS2003
("sum takes a list of int or float"). `_sum` in `restlower/_minmax.py` now
drains `iter_*` cursors and `gen.*` frames through a comprehension (the eager
model materializes them into a list; the cursor ends spent, like `list(it)`),
then folds with the existing `ps_sum_i64`/`ps_sum_f64` path. `sum(iter(xs))`,
`sum(map(...))`, `sum(gen(), start)` all work; element kinds other than
int/float keep the fence.

Pre-existing bug found on the way, out of this PR's scope: an unannotated
assignment `x = <call draining an iterator>` inside a function lowers the
right-hand side twice (the `_infer_type_of` peek plus the real pass), so the
peek's drain consumes the iterator and the real pass sees it spent -
`xs = max(v for v in it)` and `xs = sorted(v for v in it)` already mis-lower
the same way (silently empty results) independent of `sum`. The peek is
`lower/_infer.py`; annotated assigns (`xs: int = sum(it)`) are unaffected.
Filed as #1098.
