# Closing the runtime-reflection gap (2026-11-02)

Verdict first: the gap closes in ordered subsets, not all at once, and the biggest measured wins are cheap. Constant folding of the literal-name family (getattr/hasattr/setattr with a string literal, `type(x).__name__`, `issubclass` over lowered classes) plus a per-class metadata table for dataclasses and enums converts roughly half of the reflection sites we measured into native code with one focused roadmap of five small steps. Open-world getattr by runtime-computed name, `exec`/`eval`, arbitrary metaclasses, pydantic-style annotation validation at runtime, and inspect-driven tools stay island forever, because each is a mini-interpreter and the product rule is that the native binary has no interpreter inside.

## 1. What we measured

Dynamic-name uses are counted as `dyn` (name is not a string constant); literal uses as `lit`. `isinstance:named-class` means the class argument is a bare name or tuple of names, which the compiler can in principle resolve.

## 2. Classification, tier by tier

Empirical status was verified with `pyscriptc run` on tiny programs (files in `/tmp/refltest/`), not from docs. Baseline facts: `getattr(x, "lit")` and `hasattr(x, "lit")` already fold natively; dynamic-name getattr, `type(x)`, `**kwargs` forwarding, metaclasses, and class-as-value operations island-route with PS2001/PS2002; `setattr`, `vars`, `issubclass`, `dataclasses.fields`, `functools.wraps`, and `importlib.import_module` are hard fences today.

**(a) Already supported natively.** `getattr(x, "lit")`, `hasattr(x, "lit")`, `isinstance` over lowered classes (compile-time resolution, including constant bools), plain `@dataclass`, plain `Enum`/`IntEnum` member access, `def __getattr__` in the one documented shape (divergence #434), `def f(**kw)` receiving. Docs match observed behavior here.

**(b) Compile-time resolvable, statically known (fold, no runtime representation).** `setattr(x, "lit", v)` on a lowered class (a plain field store, exactly what dataclass `__init__` synthesis already emits); `issubclass(A, B)` when both are lowered classes (constant, or a runtime MRO walk over an emitted base chain if the argument is only a narrowed value type); `type(x).__name__` where `x`'s static type is a lowered class or `T | None` (fold to a string constant, or a small tag-to-name switch on the optional tag); `Color["RED"]` and `list(Color)` for enums (the compiler already keeps a compile-time `members` dict; emit a static `(name, value)` table per enum class); `getattr(x, "lit")` where the literal is a module-level constant string (constant propagation already used elsewhere); `delattr(x, "lit")` same as setattr. Cost: zero bytes at runtime for the folded forms, a few dozen bytes per enum table. This tier covers roughly 650 getattr-lit completions, 529 hasattr, 269 setattr, 111 issubclass, 585 `type()` (the `__name__` suffix subset), and enum iteration: about 1900 sites in our totals, and it is the tier that unlocks the most yt-dlp code per line changed.

**(c) Per-class runtime metadata table emitted by the compiler (the C-world answer).** This is the offsetof-style descriptor, adapted: classes already compile to C structs with compile-time field index tables (`emit/llvm/_core.py:195`), so the descriptor is mostly *emitting what the compiler already knows*. Per lowered class emit a static `ps_type_meta { name; field_count; fields[] { name, kind, offset }; method_table[] { name, fn }; base_meta* (one base, so the chain is a linked list standing in for the MRO); enum_members[] }`, wired into the object header (or reached via the struct's vtable pointer) and linked into a registry array. On top of it: `vars(obj)` and `obj.__dict__` become a synthesized dict built by walking the field table (read-only first, write-back later); `dataclasses.fields(T)` and `dataclasses.asdict(o)` become table walks; `getattr(x, dyn_name)` becomes a *closed* lookup (see (d)) only when the compiler can prove the class set, otherwise fenced. `__slots__` classes get the same table with no dict sidecar. Cost: one table per lowered class (roughly 24 bytes per field plus strings, so a 100-class program pays about 15-30 KB of rodata and a registry pointer per object or per struct type), near-zero steady-state speed cost since nothing reads the table unless reflection is called. Divergences changed: vars/__dict__, dataclasses.fields/asdict, `__slots__` entries gained native rows.

**(d) Closed-world dispatch (getattr/setattr by runtime-computed name).** When the receiver's static type is a lowered class (or union of lowered classes), `getattr(x, name)` lowers to a linear scan of that class's field/method table chained through base metas, then the existing `__getattr__` fallback, then `AttributeError`. When the receiver's type is only "some lowered class" (an erasure boundary), the compiler emits a switch over the small set of classes that flow to that value, justified by the closed import table; a miss is a runtime `AttributeError`, which is correct semantics, not a fence. The typing rule that keeps this honest: the receiver must be annotated with a lowered class or a union of lowered classes, never `Any` or `object`, and PS1104 already fires on those. The new fence is PS2005 (suggested code): "getattr on a value whose class is not in the closed set; annotate the receiver with a lowered class or route to island." `setattr` with a dynamic name is the same table walk plus a kind-checked store; mis-typed stores need a fence on the store kind, PS2006-style diagnostic. Cost: a scan is O(fields) per call, orders of magnitude slower than a static attribute load, so the diagnostic message should say "this compiles but is linear in fields; hoist to a literal getattr if hot". Coverage: the 332 dynamic getattrs, 113 dynamic setattrs, 31 dynamic hasattrs; in yt-dlp specifically, 27 + 11 + 1 sites, most in extractor info-dict plumbing.

**(e) Genuinely needs an interpreter; island forever.** `exec`/`eval` (28 sites, nearly all in pydantic and flask internals), `importlib.import_module` by computed name (55), arbitrary metaclasses and `__init_subclass__`-driven class construction (67 + 33 defs; the compiler rejects `cls` first-params today and PS1203 covers class keywords), pydantic-core's runtime annotation validation, inspect-driven tooling (`inspect.signature`, frames, source: 130 sites, concentrated in click, flask, rich), and open-world getattr on values that may not be lowered classes (flask `LocalProxy`, click parameter plumbing). These are mini-interpreters by construction; embedding one is what island mode already does, and `--fallback=cpython` is the sanctioned escape hatch. Declare them non-goals.

Share estimate across the measured totals (excluding super() and plain isinstance, which already lower): tier (b) folds about 1900 sites, (c) about 280 (`__dict__`/vars, dataclasses introspection, enum tables partially double-counted in (b)), (d) about 476 (dyn getattr/setattr/hasattr). That is roughly 2600 of the ~2900 remaining reflection sites, about 90 percent syntactically; weighted by *realistic* apps rather than pydantic, the honest number is lower, around 60 to 70 percent of sites in yt-dlp-style code, with the residual dominated by `**kwargs` forwarding (section 4) and open-world getattr in plugin systems.

## 3. Lowering sketches, fences, typing rules, costs (tiers b-d)

**(b) folds.** `setattr(x, "lit", v)`: checker resolves `lit` to a declared field with kind K; lower as the same `setattr` IR the dataclass synthesizer emits; kind mismatch at the call site is the normal type error, no new fence. `issubclass(A, B)`: both bind to lowered classes, fold to `true`/`false` at compile time; if the first argument is a value typed `T | None`, emit a tag check against `B`'s meta chain. `type(x).__name__`: fold to the class-name string when `x`'s static type is a single class; if `T | None`, a two-arm switch on the optional tag; fence (PS2001, existing message shape) if `x`'s type is `object`/`Any` or a non-lowered class. Enum: `Color["RED"]` folds through the existing compile-time `members` dict (a wrong name becomes a compile-time KeyError diagnostic, not a runtime one; document the divergence); `list(Color)` returns a synthesized list of boxed member values from the emitted table, which requires enum members to become tagged runtime values, the only nontrivial piece here. New fences: none beyond tightened messages on the `Any`-receiver cases.

**(c) metadata tables.** Runtime representation (in `runtime/`, C): `typedef struct { const char* name; uint8_t kind; uint32_t offset; } ps_field_meta;` and `typedef struct { const char* name; const ps_field_meta* fields; uint32_t nfields; const ps_method_slot* methods; uint32_t nmethods; const struct ps_type_meta* base; const char* const* enum_names; const int64_t* enum_values; uint32_t nenums; } ps_type_meta;` emitted per lowered class in the LLVM module, deduped in rodata, reachable either from a per-struct-type constant or from a registry pointer passed through the object header only for classes that opt in (compiler flag: only emit tables for classes actually reflected on, found by a pre-pass over getattr/vars/fields call sites, keeping cold programs byte-identical). Lowering of `vars(o)`: allocate a dict, walk `fields`, read each offset per its kind, insert; a `dict` result type is declared, so `vars(o)["field"]` is typed `object`-free only if the program narrows, otherwise the result is fenced (the typing rule: "vars(x) has type dict[str, X] only when all fields share declared type X; otherwise it fences; the compiler never guesses"). `dataclasses.asdict(o)` lowers to the same walk with recursive descent into nested lowered dataclasses. Divergences gained: `vars()` (new: lowered for lowered classes with all-declared field kinds), `dataclasses.fields`/`asdict` (new), `__slots__` (new: accepted, table-only).

**(d) closed-world dynamic getattr.** Pre-pass collects the set of lowered classes whose instances reach each dynamic getattr; if a receiver type is a single class, emit the direct table scan; if it is a union or an erased boundary, emit `switch (tag) { case C: scan C_meta; ... }`. Lookup order: fields, then methods, then base chain, then `__getattr__` (existing shape), then raise `AttributeError` with the runtime name. Typing rule: return type is declared by a `__getattr__` overload or inferred as the union of the matched field kinds; where the union would include mixed kinds the result fences with a message pointing at the PS1104 `Any` ban. New fences/diagnostics: PS2005 "attribute name resolved at runtime outside the closed class set" (open-world case, island route); PS2006 "dynamic setattr target kind cannot be checked" when the value type does not match every candidate field kind. Code size: one scan routine per kind-disjoint group, shared; about 1-2 KB of code plus the (c) tables. Speed: linear-in-fields per call; acceptable for config plumbing, and the diagnostic says so.

## 4. Special cases, one verdict each

**Pydantic-style models.** The compiler's own `reflection.py` docstring already names the answer: a static schema descriptor derived from annotations at compile time, not runtime reading. For a typed subset this is a new feature (`@pyscriptc.schema` or recognizing `@dataclass` plus a `validate()` builtin), not "supporting pydantic": pydantic-core is a compiled Rust extension that builds validators by exec'ing annotation expressions, which cannot survive the closed import table regardless. Verdict: build compile-time validation from annotations for the lowered subset; declare pydantic itself a non-goal; island covers it.
**Flask context locals.** `LocalProxy` dispatches every attribute through a thread-local lookup with dynamic getattr; that is open-world by design. Verdict: island forever; the honest native answer for request-scoped state is an explicit context-passing idiom, not emulation.
**`**kwargs` forwarding.** 1479 forwarding sites, the single largest fenced family. The typed escape hatch already exists in the docs: `Unpack[TypedDict]`. The small native step is to lower `f(**d)` when `d`'s static type is a `TypedDict` and `f` has a matching declared keyword set (lower to explicit named argument loads from the dict, checking presence per the TypedDict's keys at compile time; missing required key becomes a compile-time diagnostic). Verdict: worth doing, medium effort, buys large syntactic coverage in real code; untyped `**kwargs` everywhere stays PS1202/island.
**functools.wraps decorators.** User-defined wrapping decorators fence (PS1201/PS2006). A narrow native form: allow a decorator function that takes and returns the same callable type `F` and is marked identity-preserving (wraps-like), lowering to a direct call with no wrapper object, so `__name__` reads fold to the wrapped function's name. Verdict: small win, worth a step after (b); full `functools.wraps` attribute surgery stays fenced.
**dataclasses.fields/asdict.** Covered by tier (c); verdict: do it, it is mostly exposing what the compiler already stores.
**Enum.** Member access works; `Color["RED"]` and iteration are tier (b); enum members as runtime boxed values is the only real work. Verdict: fold-only first, boxed members later or never if nothing needs them.
**json/attrs-like serializers.** Once (c) exists, a generic `to_dict(obj)` over the metadata table is a small runtime helper and covers attrs-style serialization without attrs itself. Verdict: ship as a stdlib-surface builtin (`ps_to_dict` surfaced through a module in the closed table) rather than importing attrs.

## 5. Roadmap, ordered, small first

1. **Tier (b) folds**: literal setattr/delattr, issubclass over lowered classes, `type(x).__name__`, enum string lookup and iteration. Exit criteria: the tiny programs for each run natively and byte-identical (or constant-folded) under `verify`; corpus scripts that previously island-routed on exactly these constructs now go native. Buys: about 1900 measured sites, the largest step per unit of risk, and it touches only the lowerer, no runtime.
2. **TypedDict `**kwargs` forwarding.** Exit: `f(**d)` with `d: TypedDict` lowers to named-argument loads; a required-key miss is a compile-time diagnostic; `verify` green on new corpus cases. Buys: attacks the 1479-site family with the idiom the docs already recommend.
3. **Tier (c) metadata tables for dataclasses and enums**: `dataclasses.fields`, `asdict`, `vars()` read-only, emitted only for reflected-on classes. Exit: `verify` diff-clean on asdict/vars programs; rodata growth measured and under an agreed per-class budget; cold programs emit zero tables. Buys: about 280 sites and unblocks the serializer story.
4. **Tier (d) closed-world dynamic getattr/setattr** with PS2005/PS2006. Exit: yt-dlp's extractor-style dynamic-attr patterns compile natively with annotated receivers; any `Any`-receiver case produces PS2005 with the annotate-or-island message. Buys: about 476 sites; this is the step with real semantic risk, so it lands last of the native steps.
5. **wraps-shaped identity decorators** (small, optional). Exit: an identity-preserving decorator compiles and `__name__` folds. Buys: modest coverage, big ergonomics for decorator-heavy code.

Explicit non-goals, declared in docs at the same time as step 1: `exec`/`eval`, computed `importlib.import_module`, metaclasses and `__init_subclass__`-driven construction, pydantic (and any runtime annotation validator), flask/werkzeug context proxies, `inspect.signature` and frame/source tooling, and open-world getattr on untyped receivers. All of these are island-tier workloads by construction; the docs should say "island forever" for this list so the nightly compat probe stops re-litigating them.
