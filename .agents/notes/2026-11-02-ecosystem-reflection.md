# Re-ranking the runtime-reflection roadmap by ecosystem compatibility (2026-11-02)

Verdict first: of the 78 top-100 PyPI distributions we could install for CPython 3.14.9, 55 are pure Python and 23 are compiled or ship compiled dependencies; of the 55 pure ones, 22 contain zero syntactic reflection outside the constructs the previous note already folds, and only 9 (pydantic, attrs, cffi, botocore, werkzeug, jinja2, fsspec, openai, pydantic-settings) carry more than 40 reflection sites each. Re-ranking the roadmap by ecosystem compatibility does not change the order of the previous five steps; it confirms it, because the construct that unblocks the most top-100 packages is tier (d) dynamic getattr by runtime-computed name (39 packages), and the largest *new* item the ecosystem ranking adds is not a reflection step at all but the closed-import table (PS2002), which fences 16 of 18 probed packages in the current compat run and is pure non-reflection work. On pydantic: the previous note's "island forever" is overturned in part. The verdict is option (B), compile-time schema derivation for the user's own `BaseModel` subclasses, with the pydantic library itself staying on the island and the existing `pyscriptc-val` pack handling the marshalling boundary; option (D) (compiling pydantic's Python layer natively) is rejected on measured grounds: pydantic's Python layer is 46,708 lines across 105 files and uses `__dict__` (94 sites), dynamic getattr (67), `type()` (69), `issubclass` (53) and dynamic setattr (25) concentrated in exactly the class-construction machinery (`_internal/_model_construction.py`, `_internal/_generate_schema.py`, `_internal/_decorators.py`) that native lowering cannot express without becoming a Python interpreter.

## 1. The set: top 100, pure vs compiled

The list is hugovk's top-pypi-packages, 30-day window, fetched 2026-11-02 from https://hugovk.github.io/top-pypi-packages/top-pypi-packages-30-days.min.json; the repo's own frozen copy (`benchmarks/compat/denominators.json`, `top100_last_update` 2026-10-01, source https://hugovk.dev/top-pypi-packages/top-pypi-packages.min.json) already carries the same list plus a hand-maintained compiled-distribution table (`top100_native`, 22 entries), and we reused that table rather than re-deriving it. Every count below comes from either that file, `data/compat/compat.json` (generated from commit c7be3aafe528591074991042e447d2a979e3de5c), or an AST scan we ran this session (the scanner is the previous note's `/tmp/reflect_scan.py` extended with pydantic-shaped constructs; results in `/tmp/ecoscan_results.json`, not committed). Method: `uv venv --python 3.14.9`, install all 100 distributions from the list (84 resolve and install on this box; the 16 failures are covered by the repo's frozen `top100_native` classification and pinned sdists), then classify per distribution by scanning the installed tree for `.so` files and cross-checking against `top100_native`.

Split: 22 of the top 100 are themselves compiled (cryptography, cffi, pydantic-core, numpy, pandas, pillow, pyarrow, scipy, grpcio, protobuf, greenlet, rpds-py, charset-normalizer, yarl, multidict, frozenlist, propcache, lxml, jiter, regex, watchfiles, ruff) and account for 19.7 percent of the list's downloads; a further handful are pure Python but lean on compiled dependencies at runtime (aiohttp, sqlalchemy, markupsafe, wrapt, pyyaml via the extension wheels, and pydantic itself via pydantic-core). For all of these only the Python layer is in scope for this note; the extension boundary is a separate problem already half-addressed by `src/pyscriptc/native_packages.json` (orjson, msgpack, regex, cryptography, jwt packs exist; numpy, pandas, pyarrow, lxml, aiohttp, cffi, markupsafe, greenlet, charset-normalizer, pyyaml have no pack). The pure-Python layer of the compiled group plus the fully pure group is 78 distributions; our scan covered 72 of them individually (6 had no importable directory in the venv after transitive dedup).

## 3. Pydantic in depth, and the other high-leverage libraries

Pydantic v2 shape: the `pydantic` distribution is 105 Python files, 46,708 lines, and depends on `pydantic-core`, a Rust extension (one `.so`, 5,285 lines of Python shims on top). The Python layer owns annotation-to-schema conversion (`_internal/_generate_schema.py`), field/decorator collection (`_internal/_fields.py`, `_internal/_decorators.py`), model class construction (`_internal/_model_construction.py`, which uses `__init_subclass__`, metaclass-style hooks via `ModelMetaclass`, dynamic getattr and `__dict__` manipulation), and `get_type_hints`-style resolution (`_internal/_typing_extra.py`, 2 direct `get_type_hints` calls plus `typing-inspection`, a separate top-100 package that exists solely to read annotations at runtime with getattr/eval support). The Rust core owns validator execution, serialization (`model_dump`), JSON parsing (via `jiter`, also compiled), and the `SchemaSerializer`/`SchemaValidator` objects. Where reflection is used, measured: `__dict__` 94 sites (instance state access in ` BaseModel.__repr__`, `model_copy`, `__setattr__`), `type()` 69, dynamic getattr 67, `issubclass` 53, dynamic setattr 25, metaclass hooks 10, `__mro__` 12, `__fields__` reads 30, concentrated in `main.py` (25 sites), `v1/main.py` (14), `_internal/_generate_schema.py` (10), `_internal/_fields.py` (9), `_internal/_decorators.py` (8). All of the hot machinery is exactly tier (e): class construction driven by runtime annotation reading.

Options, with estimates:

(A) Island for pydantic with a fast marshalling boundary for user models. This is what exists today: `native_packages.json` routes `pydantic` and `pydantic-core` to the `pyscriptc-val` curated pack (issue #377 format), so a native program can hold pydantic models as island values and cross the boundary for validation. Cost: every model field access from native code crosses into boxed CPython; the models never get native struct layout; FastAPI-shaped workloads (models touched on every request) pay the boundary on each access. Coverage of real usage: 100 percent of pydantic's API, at island speed.

(B) Compile-time schema from annotations for the user's own BaseModel subclasses, lowered natively; pydantic itself stays island. The compiler derives, at compile time, from the annotations the user already wrote (typed-first holds: no guessing, unsupported annotations fence as usual), the same validation-and-dump plan pydantic-core would build, and emits a native struct plus generated `model_validate`/`model_dump` code. A subset constraint: str, int, float, bool, bytes, list[T], dict[K,V], Optional, Literal, nested user models, and constraint `Field()` metadata mapped to emitted comparisons; anything else (forward references through strings, arbitrary validators calling into pydantic APIs, discriminated unions) fences the class back to the island. This is the "static schema descriptor" that `src/pyscriptc/reflection.py` already names as separate work, generalized from dataclasses to a pydantic-API-compatible surface. Size: L (schema derivation, a `ps_model_dump`/`ps_model_validate` runtime surface, JSON integration with the existing orjson pack). Risk: medium; it is a new language feature (owner decision: a `@pyscriptc.schema`-style opt-in or automatic recognition of `BaseModel` subclasses in the frozen-gate area) and it must fence loudly rather than silently diverge on unsupported field types. Coverage: this is how FastAPI request/response models, pydantic-settings, typer option models and most SDK clients actually use pydantic: a declarative model class with annotations, validated against JSON-shaped data. We estimate 70 to 80 percent of real usage is declarative models of JSON-shaped types; the remainder (custom validators with imperative logic, `RootModel`, dynamic `create_model`) stays island.

(C) Native reimplementation of a subset in the typed subset with the same API. Writing a `basemodel.py` that compiles natively and shadows `import pydantic`. Size XL, risk high: it forks the API (validators, `model_config`, `Annotated` constraints, `WithDocsAnnotations` all drift), and pydantic's own test suite (the compat2 corpus already carries 650 attr tests as oracles; pydantic's is larger) becomes the compatibility contract forever. No ecosystem payoff over (B) except running pydantic's *internal* classes natively, which nobody needs. Reject.

(D) Support pydantic's Python layer natively, keep pydantic-core as a C boundary. Measured against: 46,708 lines whose reflection density is 309 sites in our scan (about 2.9 per file, the second-highest of any top-100 package after openai), with the density concentrated in the class-construction machinery that cannot lower without metaclasses, `__init_subclass__`, runtime annotation tables and `__dict__` layout, i.e. five tier (e) fences that would each have to become language features. This is "implement a Python interpreter's object model" sized work to preserve an implementation detail, and it still leaves `typing-inspection` and `pydantic-core` schema building outside. Reject.

Recommendation: (B) with (A) as the fallback and the boundary already in place. It keeps typed-first (the schema comes from annotations the compiler checks), needs no interpreter, converts the highest-download reflection-heavy use case in the ecosystem, and the fence message for an unsupported model becomes "use this model through the island boundary" instead of "pydantic does not compile".

The other high-leverage reflection users, one verdict and one blocking construct each:

attrs (844M, 55 sites): native possible for the dataclass-like core; blocking construct is the PS1204 bare-annotated-field class body plus its `__setattr__` trap machinery (22 setattr sites, `attr:__dict__` 11). The compat2 corpus already carries attr's own tests as oracles, so this is the best-instrumented target after pydantic. Verdict: native possible, via the same tier (c) metadata table as dataclasses; attrs-the-library stays island, attrs-shaped user classes lower natively.
click (1028M): island; blocking construct is decorator composition (`@click.command()` returns untyped values, PS2006) plus `inspect.signature`-free but metaclass and getattr:dyn-dependent parameter handling. The typed idiom (argparse in the closed table) exists. Non-goal to chase click itself.
typer (dep): island; blocking construct is get_type_hints over function signatures, the one thing typer exists to do. Same verdict as click.
rich (546M): island; blocking construct is dynamic getattr for style/segment dispatch (8) plus the import table surface; rendering is string-heavy and could lower later, but nothing in the roadmap buys it soon. Non-goal near-term.
jinja2 (676M): island forever for the runtime itself (it compiles templates with exec at load time); blocking construct is exec. A compile-time-template alternative is a product question, not a compat step. Non-goal.
sqlalchemy (dep, compiled via its C speedups): island; blocking construct is descriptor protocol and dynamic getattr across its InstrumentedAttribute layer. Non-goal.
requests/urllib3 (1442M/1563M): native possible for urllib3's core after the import table widens (ssl, socket, hashlib surface); blocking construct is import-table breadth, not reflection (7 getattr:dyn sites in urllib3). Verdict: native possible, unblocked by non-reflection work.
flask/werkzeug: island forever; blocking construct is LocalProxy's `__getattr__` thread-local dispatch (werkzeug 42 reflection sites, `type()` 71). Unchanged from the previous note.
fastapi/starlette: island for fastapi (it is a pydantic consumer plus inspect.signature-driven dependency injection, 4 sites), native possible for starlette's routing layer after import table and decorators land; blocking construct for fastapi is inspect.signature; for starlette it is the import table.
httpx/httpcore (753M/750M): native possible; httpcore scans at zero reflection; blocking construct is the import table (ssl, asyncio surface). Best end-to-end native candidate in the HTTP family.
pytest (926M): scans at zero reflection in its importable layer but exists to introspect user test modules at runtime (collection is computed import plus attribute scan); verdict: island; non-goal; the deliverable there is running *user* test code natively, which the previous note's steps 1-4 already serve.
openai (359M, 200 reflection sites): island today; blocking construct is dynamic `type()`/getattr over its generated-model layer plus computed importlib for client resources. Long-term native possible only via option-(B)-style schema lowering, since it is a pydantic-shaped SDK client.
boto3/botocore/s3transfer (2672M+998M+731M): island; blocking construct is dynamic getattr as their primary plugin/wire-model dispatch mechanism (35 sites in botocore alone) plus import-table breadth in botocore. Tier (d) closed-world getattr shrinks the fence count but botocore's receivers are rarely statically typed, so PS2005 lands instead. Realistic verdict: island for the foreseeable future.

## 4. Re-ranked roadmap

Ordering by top-100 packages unblocked end to end (the honest measure: a package counts only when every fence between it and a native compile is closed), weighted by downloads in parentheses:

1. Closed import table and annotation grammar widening (PS2002-import, PS1001, PS1103, PS1106). Not reflection. Unblocks end to end: certifi, idna, tzdata, iniconfig, httpcore, sniffio, referencing, jsonschema-specifications, mdurl, annotated-doc, trove-classifiers, aiohappyeyeballs, aiosignal, itsdangerous, pyasn1-modules, grpcio-status plus big partial wins in urllib3, packaging, dateutil, pluggy, pyjwt: about 16 packages outright, roughly 8.4B downloads of the top-100 total either fully or majority-unblocked. Exit criteria measurable on the compat site: packages_full in compat.json goes from 2 to at least 12; weighted_pass moves above zero for the first time; per-package fences for certifi/idna/httpcore read 0. Effort M (surface enumeration, no new language semantics). No owner decision needed beyond queue additions, which the denominators file already freezes as a process.
2. Tier (b) folds (unchanged from the previous note's step 1: literal setattr/delattr, issubclass over lowered classes, `type(x).__name__`, enum string lookup/iteration). Unblocks: partial credit in 44 packages (type() sites), standalone unblocking in pytz, pyasn1, markdown-it-py, pathspec: about 4 packages outright, 44 partially. Effort S/M. Exit criteria unchanged; measurable as corpus scripts flipping from island to native in the nightly.
3. TypedDict `**kwargs` forwarding (previous step 2). **fwd appears in 51 of 72 packages (1,884 sites); standalone unblocking is modest (it usually rides with the import table) but it is the fence the typed idiom already names. Effort M. Exit criteria unchanged.
4. Tier (c) per-class metadata tables for dataclasses and enums (previous step 3). Unblocks the serializer story and the attrs-shaped class bodies (PS1204): partial in 26 packages (`__dict__`/vars), standalone for attrs-shaped user code. Effort M. Exit criteria unchanged (verify diff-clean, rodata budget).
5. Tier (d) closed-world dynamic getattr/setattr (previous step 4). The single largest reflection unblock by package count: 39 packages contain dynamic getattr; after (2)-(4) the honest end-to-end unblock is the subset whose remaining walls are gone, at this point urllib3, requests, rich, fsspec, tqdm, pygments partially: about 6 packages, plus deep fence reduction in boto3/botocore. Effort L, highest semantic risk, stays last among the native steps. Exit criteria unchanged plus a compat-site per-package fence delta for the packages above.
6. NEW: compile-time schema derivation (option B) for pydantic-shaped models: owner decision required, because it is a new language feature in the frozen-gate area (schema derive: does `@pyscriptc.schema` opt in, or does the compiler recognize BaseModel-shaped annotated classes automatically; either way the unsupported-annotation fence must stay a fence). Unblocks: pydantic-shaped usage end to end is not "compile pydantic", it is user models lowering natively; measurable exit: a FastAPI-shaped probe (request model, validate, dump, respond) compiles native with zero island crossings on the happy path; compat site gains a pydantic-model probe distinct from the library probe. Effort L/XL. This step also serves pydantic-settings and openai-shaped SDK clients.
7. wraps-shaped identity decorators (previous step 5, optional). Effort S. No package unblocks outright; tenacity/decorator-heavy partials.
8. NEW (small, non-reflection): PS2006 decorator-typing escape hatch documentation and a `ps_declare_decorator`-style marker, so click/typer-adjacent user code can cross. Owner decision (new fence surface). Effort S/M.

Non-goals, restated with the ecosystem ranking behind them: exec/eval (jinja2, werkzeug, flask internals), metaclasses and `__init_subclass__`-driven construction (pydantic's Python layer, anyio, h11), `inspect.signature` and frame/source tooling (click, fastapi, pluggy, rich), flask/werkzeug LocalProxy, pytest collection, sqlalchemy descriptors, openai/boto3 client dispatch, and any C/Rust extension boundary (numpy, pandas, lxml, aiohttp, cffi, markupsafe, greenlet, charset-normalizer, pyyaml wheels, watchfiles, ruff). The zero-CPython-at-runtime absolute stays not-a-requirement; the island tier remains the answer for all of the above, and the nightly probe should keep scoring them as island-supported rather than re-litigating.
