# Old-lane compatibility to revoke or drop (research note, epic #817)

Date: 2026-11-06. Branch: `work/res-compat-drop`. Docs only. Owner question answered: the new MIR lane reports 32 of 33 in-slice on the visible corpus (`uv run python scripts/mir_coverage.py`, measured in `.agents/plans/2026-11-06-v090-user-centered-flip.md` section 2) but slice parity is no longer the win metric; the flip gate is user-centered per the same plan's section 3 proposal. This note catalogs every old-lane parity mechanism, costs it, what it protects, churn cost over the last 100 commits, and a retire verdict. All line counts are `wc -l` on this branch; churn counts are `git log --oneline -100 -- <paths>` commit counts (squash merges hide real conflicts, so co-touch is the proxy).

## 1. Catalog of old-lane parity mechanisms

Byte-identical per-function LLVM. `MirBlock.hint` and `MirBlock.label_id` (`src/pyscriptc/mir.py` lines 492-503, `MirBuilder.start_block` lines 715-729) record the direct path's lazily allocated `fresh()` label numbers so `miremit._label` (lines 610-635) can print identical `.ll` text; `mirlower.reserve_label` (lines 1611-1619) plus roughly 40 `reserve_label`/`label_id=` call sites across `emit_if`, `emit_while` and the try lowering (lines 1775-2080, about 80 lines of label plumbing) replay the direct emitter's `_stmts.py` `fresh("then")`/`fresh("while.cond")` ordering from `src/pyscriptc/emit/llvm/_stmts.py` lines 100-228. Tests it costs: `tests/test_mir_leaf.py` `TestByteIdentity` (lines 98-124) parametrized over 43 entries in `LEAF_SAMPLES` (lines 51-95) plus `tests/test_mir_hashseed.py` (60 lines, three `PYTHONHASHSEED` subprocess runs per fixture) plus `tests/test_mir_differential.py` (104 lines, asserts whole-file `mir == direct` per `define` over the in-slice corpus). What it protects: incidental emitted shape only. Label numbers and alloca placement are not semantics; the runtime A/B differential (`scripts/runtime_ab.py`, 404 lines) and the scorer parity receipt (`scripts/compat_mir_flip.py`, 204 lines) cover behavior. Churn: `miremit.py` touched by 25 of the last 100 commits, `test_mir_leaf.py` by 23, `mirlower.py` by 21, `mir.py` by 17.

Side channels. `MirFunction.helpers` (`mir.py` lines 566-571) is a `dict[int, str]` keyed by instruction index carrying stringly-typed markers (`"print"`, `"builtin:<name>"`, `"abi <symbol>"`, `"method:join"`, `"format:<n>"`, `"strget"`, `"trypack <names>"`, `"trycall <outline>"`, `"<helper> <tag>"`) written at 14 sites in `mirlower.py` (lines 1900-2568) and parsed back by string prefix in `miremit.py` (lines 666, 948, 989, 1015-1040); it is deliberately omitted from `serialize()`, so the MIR digest cannot see which helper a `MIR_COPY` calls, a real integrity blind spot (inference: `a // b` and a different helper op with the same operand shape hash identically). `call_args` (mir.py 572-575) and `callees` (mir.py 576-582) are `dict[int, ...]` keyed by instruction index because the four-int instruction has no room for a variable argument list; `miremit._instr_index` (lines 997-1002) reverse-scans `dsts` to recover an index for the helpers lookup. Cost: about 35 lines of field plumbing in `mir.py`, 14 write sites in `mirlower.py`, roughly 60 lines of marker parsing in `miremit.py`, plus the digest blind spot. What it protects: emission fidelity to the direct path's helper-call spellings, i.e. incidental shape, plus the try outline naming. Churn: `mir.py` 17 commits, `mirlower.py` 21, `miremit.py` 25 in the last 100.

Op-id ordering constraints. Hand-numbered op constants with gaps and jumbled order (`MIR_ANDW = 29` before `MIR_NEWSEQ = 30-34`, `MIR_ORW`/`MIR_XORW` at 35-36, class ops 37-39, `MIR_MAP_PUT = 40`, try ops 41-52, `MIR_INITCALL = 53`; `mir.py` lines 73-240). The "append above the highest id" convention is the de facto rule and the collision point; ids are baked into `serialize()` output so renumbering changes every digest. Cost: the literal-table duplication it forces (below) and merge collisions, not parity per se. What it protects: digest stability of the MIR hash, which is a real contract (`module_hash` in `mir.py`) but not yet a frozen gate file. Churn: every op-adding PR touches `mir.py`, `mirlower.py`, `miremit.py`, `mirverify.py`, `mirprint.py`; the plan measured 22 of the last 100 hotspot commits touching two or more op files.

Literal-table duplication (a parity-adjacent cost, not old-lane parity itself but the same hotspot): `mirverify.py` lines 65-135 re-spell `_OP_ARITY` as a 53-entry int-literal dict plus `_EXTRA_TERMINATORS` and `_TAGLESS_VALUE_OPS`; `miremit.py` lines 171-288 re-spell `_MIR_TERMINATORS`, `_OP_ARITY`, `_OP_RESULT_TYPE`; `mirprint.py` keeps `OP_NAMES` (about lines 87-140) and `_TERMINATORS` (line 144). Cause: `mir.py` module-level tables bind global slots that do not ride the self-host package export table (`miremit.py` lines 171-180 comment). About 200 lines of duplicated tables across three files, drift caught only by tests. Stage A of the flip plan already proposes function accessors or a generated file; verdict below.

Slice predicates that only mirror the old emitter's accepted shapes. `mirlower.supported_*` spans lines 301-1350, about 1050 lines of predicate code. Most of it is the coverage boundary (legitimate), but several predicates encode emitter artifacts: `_rt_args_order_ok` (lines 780-795) rejects a runtime-ABI call like `ord("x")` mixed with a computed argument because the direct emitter materializes a top-level str const lazily at the call position while MIR evaluates arguments left to right; the rejection is about instruction order, not semantics (docstring lines 780-786 say exactly this). `_rt_call_shape` (lines 722-779) and `_rt_call_symbol` (lines 797-822) hard-code the direct emitter's `_emit_abi`/`_emit_math` symbol spellings (`ps_math_sqrt`, `ps_sum_i64`, `ps_seq_repeat`, `ps_int_from_bytes`, `ps_int_from_base`). `_supported_print` (lines 502-533) re-implements the direct `_print_one` walk including its kwargs exclusions. `emit/_mir_in.py` (245 lines) re-walks the same dict nodes to produce fallback-reason telemetry; its `out_of_slice_reason` is report-only. What it protects: the slice boundary that keeps the strangler lane honest; the quirk-mirroring subset protects byte parity. Churn: `emit/_mir_in.py` 3 commits, predicates ride `mirlower.py`'s 21.

Tests that pin old-lane output. Beyond the MIR tests above: `tests/test_emitter_goldens.py` (134 lines) plus `tests/fixtures/backend/llvm/*.ll` goldens pin the direct emitter's bytes per IR node kind; `tests/test_mir_print.py` (59 lines) plus `tests/fixtures/mir_print/*.mir` goldens pin MIR text (these protect the printable-IR goal, not old-lane parity); `tests/test_mirverify_negative.py` (406 lines) pins verifier codes on hand-built broken functions (pure MIR semantics, keep). What the emitter goldens protect: the direct lane's own stability while it exists as the `PYSC_MIR=0` escape hatch; they retire with the direct emitter at v0.10.0.

IR_HASHES coupling. None found: `grep -rn "mir" benchmarks/compat2/*.py benchmarks/compat2/probes/*.py` returns no MIR references; `IR_HASHES.json` and `TIR_HASHES.json` hash the dict IR and TIR, which the MIR lane does not feed. The one real coupling is the scorer cache: `benchmarks/compat2/cache.py` `cache_key` is (probe hash, oracle version, compiler file hash) and does not include `PYSC_MIR`, so `scripts/compat_mir_flip.py` forces `--no-cache` on both lanes (its docstring lines 14-22). A future caller that forgets `--no-cache` compares a lane with itself.

The `PYSC_MIR` escape hatch. `miremit.py` lines 123-133 (`MIR_ENV`, `MIR_ON`, `MIR_OFF`, `MIR_DEFAULT = False`), `mir_opt_in` lines 291-302, CLI call site `cli/_main.py` line 1751, contract pinned by `tests/test_mir_escape_hatch.py` (78 lines) and `.agents/docs/mir-escape-hatch.md`. Cost: about 20 lines of code plus one test file. What it protects: the rollback path and the A/B differential's "off" lane; it is the mechanism every parity measurement uses. It must live until the direct emitter is deleted at v0.10.0.

The splice architecture (context for the verdicts): `miremit.MirEmitter.emit` (lines 383-408) runs the full direct `Emitter.emit` and `_splice` (lines 410-437) text-replaces each in-slice function body, so today every compile pays for both lanes and the byte-parity machinery exists to make the splice invisible. After the flip the MIR lane should own whole-module emission; the runtime header, ABI declarations, helper bodies and entry point are already shared (`emit/llvm/` modules), so this is deletion of the splice, not new code.

## 2. Verdicts

Keep now (protects user behavior or is the measurement substrate): the `PYSC_MIR` escape hatch and `test_mir_escape_hatch.py` until v0.10.0; `scripts/runtime_ab.py`, `scripts/compat_mir_flip.py`, `scripts/mir_perf_ratio.py` and their tests; `tests/test_mirverify_negative.py` and the verifier itself (the MVS verifier is a flip-gate component); `tests/test_mir_print.py` goldens (printable IR is a stated goal); `emit/_mir_in.py` telemetry (it is the fallback-share metric the amendment requires); the slice-predicate mechanism `supported_*` as the coverage boundary.

Retire at the flip (v0.9.0, same PR that sets `MIR_DEFAULT = True`): the byte-equality assertions, not the tests' existence. Concretely: `TestByteIdentity.test_direct_vs_mir_bytes` in `test_mir_leaf.py` (lines 100-104) and the `assert mir == direct` in `test_mir_differential.py` (line 81) stop being gates the moment the flip lands, because their replacement protection already exists and is stronger: `runtime_ab.py` compares executed stdout/stderr/exit codes (semantics, not shape) and `compat_mir_flip.py` compares scorer outcomes on the visible corpus. Recommended default: keep the tests running as a report-only lane for one release rather than deleting them in the flip PR, then delete with the direct emitter at v0.10.0; the LLVM half of `test_mir_hashseed.py` likewise becomes MIR-internal determinism only. The `label_id`/`hint` plumbing (`mir.py` 492-503, 715-729; `mirlower.py` `reserve_label` and its call sites; `miremit._label` 610-635) can be deleted in the same window once nothing asserts byte equality; it is about 120 lines plus the `MirBlock` constructor churn. The `_rt_args_order_ok` predicate (mirlower.py 780-795) and the symbol-spelling checks in `_rt_call_shape`/`_rt_call_symbol` should be relaxed at the flip, admitting the shapes they rejected for emission-order reasons only.

Retire after dict-IR deletion (v0.10.0): the direct emitter `emit/llvm/` (6087 lines per the plan's measurement), `emit/_ir.py` seam reads inside the MIR lane, `tests/test_emitter_goldens.py` and `tests/fixtures/backend/llvm/`, the `helpers` string channel and `_instr_index` reverse lookup (replaced by typed op payloads, see section 3), the `PYSC_MIR` env var and `test_mir_escape_hatch.py` (the hatch has nothing to escape to), the splice in `miremit.emit`/`_splice`, and the duplicated literal tables in `mirverify.py`/`miremit.py`/`mirprint.py` (Stage A single-sourcing lands before this regardless). `call_args`/`callees` index-keyed dicts can stay or move to a serialized side table in the same cleanup; they are not old-lane parity, they are the four-int shape's argument channel.

Op ids: keep ints and the append-only convention through v0.9.0 because ids are baked into `serialize()` digests; the rename to name-keyed ops or a `MIR_HASHES.json` gate (plan note M-5, `.agents/notes/2026-11-06-mir-digest-gate.md`) is a v0.10.0 decision, matching plan section 6 item 2. Do not renumber early: it changes every digest for zero user-visible gain.

## 3. Slice work already merged that encodes old-emitter quirks

Five concrete examples, all in `mirlower.py`/`miremit.py` with the better design:

1. `_rt_args_order_ok` (`mirlower.py` lines 780-795): admits an ABI call only while every argument after the first str const is itself a const, because the direct emitter materializes str consts lazily at the call instruction while the MIR lane evaluates left to right. This fences real user code (`ord(s)` beside a computed argument, `int(text, base)` forms) for an instruction-scheduling artifact. Better: materialize each const at its own position (SSA already gives each value one def site) and delete the predicate at the flip; no new machinery needed.

2. Eager `MIR_COPY` per name read (`mirlower.py` `load_slot` lines 2097-2112, `store` lines 2082-2095): every read of a name emits a copy "so the loads land in the same source order the direct walk produces" (docstring cites issue #871). MIR is SSA; these copies exist only so `miremit` can count reads and reproduce one `load` per read against an alloca. Instruction count inflates by roughly one op per name access on every lowered function. Better: operands reference the SSA value directly and the emitter promotes slot values to allocas or registers; the copies disappear with byte identity at the flip.

3. The `helpers` string channel (`mirlower.py` 14 write sites lines 1900-2568; `miremit.py` marker parsing lines 666, 939-995, 1015-1040; `mir.py` 566-571): try pack/call, print, builtin, abi, method, format and helper-op spellings ride a `dict[int, str]` that `serialize()` deliberately omits. The emitter recovers the index by scanning `dsts` (`_instr_index`, miremit.py 997-1002) and dispatches on string prefixes. Better: typed payloads, a `MIR_ABI_CALL`/`MIR_RT_CALL` op whose symbol is a `MIR_S` constant operand (consts are already serialized and digested), a `MIR_PRINT` op, and a serialized side table for the try outline name list; this also closes the digest blind spot in one move.

4. `label_id`/`hint` label replay (`mirlower.py` `reserve_label` 1611-1619 plus ~40 reservation sites in `emit_if`/`emit_while`/`emit_try`/`_emit_try_finally` lines 1775-2080; `miremit._label` 610-635 including the `divmod(bid - 1, 3)` fallback that reconstructs unhinted `if` labels): the lowerer re-enacts the direct emitter's lazy `fresh()` numbering so nested `if`s inside arms keep identical label numbers. It blocks any label scheme that does not mimic `_stmts.py` order and adds a `MirBlock` field plus constructor parameter churn on every block. Better: sequential `L<bid>` labels once byte parity retires; block ids are already deterministic.

5. `MIR_COPY` standing in for runtime-helper binary ops (`mirlower.py` `emit_binary` helper path lines 2555-2568, `_W_HELPER_OPS`/`_D_HELPER_OPS` tables lines 288-299): `//`, `%`, `/`, `**`, `<<`, `>>` lower to `MIR_COPY` with the `ps_*` helper name in `helpers`, so the serialized MIR cannot distinguish `a // b` from `a / b` (both are copy-shaped with different invisible markers). Better: real ops per helper family (`MIR_IDIVW`, `MIR_MODW`, `MIR_SHLW`, ...) or a typed helper operand in `arg3`; either fits the Stage A op spec and makes the digest honest.

A sixth, structural: the whole try lowering (`mirlower.py` `_emit_try_plain`/`_emit_try_finally` lines 1933-2080, about 150 lines, twelve try ops `MIR_TRYPACK`..`MIR_UNREACH`) re-spells the direct emitter's outline-function callsite sequence including `ps.try.N` naming (`_outline_name` line 1881) rather than a first-class try region; acceptable for v0.9.0 because M-3 already landed it, but the CFG-native redesign belongs to the optimization-pass work, not to further slice expansion.

## 4. Does lowering the bar change what sessions build next

Slice parity is effectively exhausted: 32 of 33 non-fenced corpus functions in slice, and the remaining blockers named in `.agents/notes/2026-11-06-mir-coverage-gap-map.md` (recursion policy residue, `binary_trees` class shapes, direct-lowerer unfences `shift`/`sieve`/`advance`/`check`) are `lower/` work, not MIR work. Spending sessions on the last slice percent buys almost no user-visible fences. Ranked by user-visible fences cleared (`census_self` families from the flip plan section 2) per effort:

1. 2. 3. R-2 typed coro/generator port (`.agents/notes/2026-11-06-typed-coro-generator-lowering.md`): XL, but it is also the single largest dict-IR deletion (`coro.py` 2222 lines per `.agents/notes/2026-11-06-dict-ir-deletion-map.md`) and unlocks `yield`, a top user-visible construct. 4. Union types and multi-arm optionals: 47 census fences plus PS1101/PS1102 checker fences, effort M, mostly typed-HIR/checker work with little MIR surface.
5. Generic aliases and class-body constructs: 25 plus 6 census fences, effort M, HIR-side; also feeds the class-shape corpus blockers (`binary_trees`, `gcd_lcm`) that slice predicates currently reject.

## 6. Risks (recommended defaults)

1. Retiring byte identity before the runtime A/B set covers every in-slice corpus function could ship a silent miscompile the byte gate would have caught. Default: gate the relaxation on the FR-2 extension (all in-slice corpus functions in the `runtime_ab.py` default set) being merged first; until then byte identity stays a gate even after `MIR_DEFAULT` flips.
2. The `helpers` digest blind spot means the MIR hash cannot see helper-spelling differences; retiring parity work that relies on `module_hash` for drift detection inherits the hole. Default: before deleting `helpers`, either serialize it or replace it with typed ops per section 3 item 3; add a drift test either way.
3. The scorer cache key omits `PYSC_MIR`; `compat_mir_flip.py` guards with `--no-cache` but nothing stops a future caller. Default: keep the `--no-cache` enforcement in the script and add `PYSC_MIR` to `cache_key` when the lane set stabilizes, or a test asserting the flip receipt always passes `--no-cache`.
4. The direct emitter is the A/B reference; deleting it at v0.10.0 removes the differential's "off" lane. Default: `PYSC_MIR=0` and `emit/llvm/` are deleted in the same v0.10.0 change, never earlier; `runtime_ab.py` keeps a frozen direct-lane binary artifact if post-deletion differential is still wanted (decision deferred to v0.10.0 planning).
5. Reporting slice coverage without gating it can let the number drift while sessions chase fences; conversely gating on it revives the quirk-mirroring predicates. Default: keep `mir_coverage.py` in CI as a report with the 60 percent kill rule, and require every slice-admission PR to name the user-visible fence or corpus function it clears, per the plan's Stage 4 rule.
